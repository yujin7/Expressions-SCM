## 一、库存科学

### 安全库存

```
SS = z × √( L̄·σ_d²  +  d̄²·σ_LT² )
                          ↑ 交期方差乘的是「日均需求的平方」
```

**关键洞察**：σ_LT 前面的系数是 d̄²。对高动销 SKU，**压低供应商交期波动
往往比提升预测准确度更有效**——因为交期波动被需求量放大了两次。

- 世界级：交期方差进公式，且知道该先治交期还是先治预测。
- 平庸：安全库存＝「按分层给周数」——完全无视交期与补货批量。这是有文档记载的常见失败。

本系统：`rules/safety-stock.ts` 已实现完整公式，样本不足时诚实降级为兜底天数并标注原因。
交期波动来自 `rollup_supplier_lead`，随 PO→收货历史自动积累。

### 多级库存（MEIO）

核心不是「每个点都设缓冲」，而是**决定缓冲放在哪里**。中心库存靠风险池化覆盖多个下游点，
边缘库存只覆盖一个点。各仓统一按「天数覆盖」设缓冲 → 每一级都重复囤货，总库存虚高。

### 时间分段净需求

```
逐期：期初 + 计划到货 − 毛需求 = 逐期可用余额
首次跌破安全库存的那一期 = 真正的需求点
建议下单日 = 短缺日 − 生产周期
```

- 世界级：逐日/逐周分桶（高动销与易过期品用日桶）。
- 平庸：毛需求＝日均 × 覆盖天数，把未来压成一个数。

本系统：`rules/timephased.ts` 已按此实现；`rules/projection.ts` 画同源曲线
（**共用同一到货/消耗输入，避免「图与建议不一致」**）。

### ABC/XYZ

分层的意义是**分策略**：不同服务水平目标、不同复盘频率、不同预测方法路由
（间歇性需求走 Croston/SBA/TSB，而不是套同一个指数平滑）。
只用来染个色、不驱动任何策略差异 = 白做。

## 二、预测

**先证明你比朴素预测强。** 30 万+ 预测的研究里，**52% 不如随机游走**（即「下期＝上期」）。
这就是 FVA（预测价值增量）的由来：逐环节衡量准确度贡献——
朴素 → 统计 → 人工调整 → 共识，哪一环真的加了分。

**指标选择**：
- MAPE 在实际＝0 时无定义（间歇性 SKU 天天撞上），且把一个零星小 SKU 与主力 SKU 等权。
- **WMAPE/WAPE（按量加权）才是决策级指标。**
- **偏差（bias）与随机误差必须分开跟踪**——随机误差会互相抵消，系统性偏差会累积。

本系统 `rules/backtest.ts` 已经算 MAPE + WAPE + bias，并显式注明「实际=0 时 MAPE 无定义」，
`biasLabel()` 还把偏差翻译成后果（「系统性高估 → 备货偏多」）。**这已经是好实践。**
缺的是 FVA 的地基：没有和朴素预测对比，所以无法回答「Holt 到底有没有比『上月照抄』强」。

## 三、美妆特有

### 效期是渠道约束，不是仓库报表

天猫对部分美妆类目定义**临期 = max(总保质期的 2/10, 100 天)**。
其他平台对剩余 90 / 180 天以下有临期标注与不可退要求。

**含义：剩余效期决定这批货能不能进这个渠道**，不是月底导出来看看的数字。

> **本系统的具体差距**：`skus.nearExpiryDays` 缺省 90 天，而保质期缺省 1095 天（D13）。
> 按 2/10 规则应是 **219 天**。一批剩 150 天的货，系统判「健康」，渠道可能已判「临期」。
> 落地前应按实际渠道合同核准该阈值——这不是代码 bug，是**参数口径与外部规则脱节**。

### 批号是法定追溯标识

《化妆品监督管理条例》《化妆品生产经营监督管理办法》下，**注册人/备案人（品牌方）
对委托生产承担全部质量安全责任，须监督生产全过程**；**批号是指定的唯一追溯标识**。

本公司做 委外（委托生产）＝ 品牌方就是责任主体。这把批次追溯从「有更好」抬升到**合规义务**。

### 召回就绪度是可测的

- **正向**：批次 → 发货 → 渠道/客户
- **反向**：批次 → 工厂批 → 原料/包材批 → BOM 版本
- **物料平衡**（投入 vs 产出 vs 报废对得上）
- 用**定时模拟召回**测量，目标通常 2–4 小时。一上一下（one-up/one-down）是法规底线，不是完整族谱。

> 本系统：`batches` 主档已建但 1.0 关闭；台账批次列是哨兵，`batch_stocks` 是参考层。
> **批次入账必须与 FEFO 出库同时上线**——余额唯一键含 batchId 且实时仓禁负数，
> 只上一半会打断正常发货。这是已知的强耦合，别拆开做。

### 行业基准（用于判断我们的数字是否离谱）

| 指标 | 美妆行业 |
|---|---|
| 库存周转 | 4–9 次/年（41–91 天）；中型品牌目标 45–70 天；3 次是盈利底线 |
| 持有成本 | 20–30%/年，其中**资金成本 8–15%** 就大于仓储+服务+损耗之和 |
| 损耗 | 约 3.2% of sales；报废是**结构性**的（停色号、换配方、过期），不是意外 |
| ODM/OEM 交期 | 新配方 45–60 天（含配方确认+包材印刷+生产）；返单 20–30 天 |
| MOQ 档位 | 常见 500 / 1,000 / 2,500 |

## 四、例外与告警

**第一代控制塔失败的原因就是什么都报。** 计划员一小时收几十条告警，几天内就学会全部忽略。

下一代例外层的评判标准是：**降噪、优先级排对、路由对**——而不是覆盖率。

判据：
- 命中才渲染，无命中不占位（本系统 `data-health` 的 `structural` 就是这个模式）。
- 抑制 ≠ 隐藏：抑制必须带原因、带计数、可人工推翻（`rules/fusion.ts` 的 refGap 抑制）。
- 阈值固定 = 不认识「这条 SKU 本来就这么波动」。统计控制带（`rules/spc.ts`）比固定阈值强。
- 实测过的降噪才算数：refGap 上线后 128 个「紧急」收敛到 22 个真的。

## 五、自动化的边界

Gartner 预计**到 2027 年底 40%+ 的 agentic AI 项目会被取消**，多数因为价值不清。

生产中真正有效的模式：**受约束、可逆、小的决策自动跑；不可逆或高风险的必须人审。**

这正是本系统 R13 教义（守护式自动化/人工闸）：自动化只产**草稿**，审批永远是人；
驾驶舱洞察「仅陈述不开单」。D33 自动链也照此办理——自动开 WO/JG 草稿、
dry-run 预览、防雪崩护栏（每 WO ≤8 批、needsReview BOM 排除、全局急停）。

**不要为了「更智能」去松这个闸。** 它是这个系统能被业务信任的原因。

LLM 计划助手真正能落地的，都做到了：**扎根于底层计划数据 + 强制引用 + 拒答模式 + 审计留痕。**
可解释性是硬约束，不是加分项。

## 六、主数据

**45% 的新品上市延迟源于主数据缺陷；只有约 25% 的组织真的在测量主数据质量。**
主数据质量导致计划系统失败的频率，高于算法选型。

世界级：主数据完整度是**有分数、有责任人、有闸门**的（缺生产周期就不该进补货建议）。
平庸：主数据是「导入时清洗一次」的一次性动作。

本系统：`report/data-health.ts` 按 skuType 裁剪适用维度评分，另有结构性告警（BOM 嵌套）。

## 七、渠道与口径

**「一个数字（one number）」是个神话**——Gartner 明确这么归类。
成熟的 S&OP/IBP 产出的是**一个达成共识的计划**，用量和钱两种口径表达，
且把需求计划与财务目标之间的**缺口显式量化并指派责任人**，而不是硬压成零。

这恰好是本系统 refGap 的做法：不假装系统口径就是全公司口径，
而是把差量标出来、给原因、给责任动作。**保持这个习惯。**

消费品牌应基于**售出（sell-through）与渠道库存**做计划，而不是自己的发货（sell-in）。
本系统的销售真相源是聚水潭（电商实际出库），方向正确。

中国「一盘货」四层共享库存模型：**账实分离**（物理 vs 逻辑库存）、
共享策略（比例共享/区域共享/滞销强制共享）、渠道**预占**（预售与大促）。
本系统 40 逻辑仓 / 10 物理仓的设计与「账实分离」同源。

## 八、本系统当前的具体差距（按价值排序）

1. **临期阈值与渠道规则脱节**（见三）——缺省 90 天 vs 2/10 规则的 219 天。需按渠道合同核准。
2. **预测无朴素基准**——`backtest.ts` 有 MAPE/WAPE/bias，但没回答「比『上月照抄』强吗」。
   加一列朴素预测误差即可，这是 FVA 的最小可用形态。
3. **批次追溯未闭环**——合规义务在品牌方。批次入账 + FEFO 必须同时上线。
4. **召回就绪度从未演练**——正向/反向/物料平衡三件事目前无人验证过能否在数小时内做出。
5. **交期波动待数据积累**——公式已接通，但 `rollup_supplier_lead` 目前 0 行，
   因为系统里只有 3 条 PO 行。跑起来会自己长出来，不是 bug。
