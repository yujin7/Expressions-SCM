## 一、库存科学

### 安全库存

```
SS = z × √( L̄·σ_d²  +  d̄²·σ_LT² )
                          ↑ 交期方差乘的是「日均需求的平方」
```

**关键洞察**：σ_LT 前面的系数是 d̄²。对高动销 SKU，**压低供应商交期波动
往往比提升预测准确度更有效**——因为交期波动被需求量放大了两次。

- 可靠做法：交期方差进公式，并用数据判断该先治交期还是先治预测。
- 风险信号：安全库存只按分层给固定周数，忽略交期、服务目标与补货批量。

本系统：`rules/safety-stock.ts` 已实现完整公式，样本不足时诚实降级为兜底天数并标注原因。
交期波动来自 `rollup_supplier_lead`，随 PO→收货历史自动积累。

### 多级库存（MEIO）

核心不是「每个点都设缓冲」，而是**决定缓冲放在哪里**。中心库存靠风险池化覆盖多个下游点，
边缘库存只覆盖一个点。各仓统一按「天数覆盖」设缓冲 → 每一级都重复囤货，总库存虚高。

### 时间分段净需求

```
逐期：期初 + 计划到货 − 毛需求 = 逐期可用余额
首次跌破安全库存的那一期 = 真正的需求点
建议下单日 = 短缺日 − 生产周期
```

- 可靠做法：按实际决策周期逐日/逐周分桶，高动销与易过期品通常需要更细粒度。
- 风险信号：毛需求只等于日均 × 覆盖天数，把到货和消耗时点压成一个数。

本系统：`rules/timephased.ts` 已按此实现；`rules/projection.ts` 画同源曲线
（**共用同一到货/消耗输入，避免「图与建议不一致」**）。

### ABC/XYZ

分层的意义是**分策略**：不同服务水平目标、不同复盘频率、不同预测方法路由
（间歇性需求走 Croston/SBA/TSB，而不是套同一个指数平滑）。
只用来染个色、不驱动任何策略差异 = 白做。

## 二、预测

**先证明你比朴素预测强。** FVA（预测价值增量）逐环节衡量准确度贡献——
朴素 → 统计 → 人工调整 → 共识，哪一环真的加了分。

**指标选择**：
- MAPE 在实际＝0 时无定义（间歇性 SKU 天天撞上），且把一个零星小 SKU 与主力 SKU 等权。
- **WMAPE/WAPE（按量加权）才是决策级指标。**
- **偏差（bias）与随机误差必须分开跟踪**——随机误差会互相抵消，系统性偏差会累积。

本系统 `rules/backtest.ts` 算 MAPE + WAPE + bias + **FVA**，显式注明「实际=0 时 MAPE 无定义」，
`biasLabel()` / `fvaLabel()` 把指标翻译成后果与出路。

历史实验说明复杂模型可能输给朴素基线，但历史样本不等于当前模型结论。每次引用 FVA、
WAPE 或适用算法前，必须锚定 revision、数据窗口、SKU 范围与回测方式；当前结果从
`docs/NOW.md` 链接的证据取得。

## 三、美妆特有

### 效期是渠道约束，不是仓库报表

渠道临期口径依赖平台合同、品类、市场与生效日期，可能按总保质期比例、固定剩余天数
或两者组合定义。

**含义：剩余效期决定这批货能不能进这个渠道**，不是月底导出来看看的数字。

> **项目约束**：系统阈值只是参数，不能代替渠道合同。硬编码或调整前，先在
> `docs/spec/CURRENT.md` 登记适用范围、来源、生效日与业务 owner；当前覆盖与缺口见
> `docs/NOW.md` 的证据链接。

### 批号是法定追溯标识

批次/批号是质量放行、效期、投诉与召回的重要追溯键，但具体责任主体、标识和留存义务
取决于产品分类、市场、角色与生效法规。实施硬门前从 `authoritative-sources.md` 复核当前
一手来源，并由法律/合规 owner 确认适用性；不要从「委外」一词自动推导法律结论。

### 召回就绪度是可测的

- **正向**：批次 → 发货 → 渠道/客户
- **反向**：批次 → 工厂批 → 原料/包材批 → BOM 版本
- **物料平衡**（投入 vs 产出 vs 报废对得上）
- 用定时模拟召回测量 time-to-scope、联系覆盖、数量平衡和闭环证据；目标值由当前风险和
  合规决议确定，不从行业传闻复制。

> 项目是否已具备真实批号、批次记账和 FEFO，只能从 `docs/NOW.md`、当前 schema、写路径与
> 端到端证据判断。批次键进入余额前，应把入账、资格、FEFO、冲销和迁移作为一个闭环验证。

### 基准纪律

库存周转、持有成本、损耗、交期和 MOQ 必须使用本企业、对应品类/市场和明确期间的可追溯
基线。外部行业数字只能作带来源与适用范围的 sanity check，不能直接成为目标或硬门。

## 四、例外与告警

控制塔如果什么都报，用户会迅速忽略全部告警。

下一代例外层的评判标准是：**降噪、优先级排对、路由对**——而不是覆盖率。

判据：
- 命中才渲染，无命中不占位（本系统 `data-health` 的 `structural` 就是这个模式）。
- 抑制 ≠ 隐藏：抑制必须带原因、带计数、可人工推翻（`rules/fusion.ts` 的 refGap 抑制）。
- 阈值固定 = 不认识「这条 SKU 本来就这么波动」。统计控制带（`rules/spc.ts`）比固定阈值强。
- 降噪效果必须在当前范围重测，并同时报告命中、抑制、误报和处置结果。

## 五、自动化的边界

生产中真正有效的模式：**受约束、可逆、小的决策自动跑；不可逆或高风险的必须人审。**

这正是本系统 R13 教义（守护式自动化/人工闸）：自动化只产**草稿**，审批永远是人；
驾驶舱洞察「仅陈述不开单」。D33 自动链也照此办理——自动开 WO/JG 草稿、
dry-run 预览、防雪崩护栏（每 WO ≤8 批、needsReview BOM 排除、全局急停）。

**不要为了「更智能」去松这个闸。** 它是这个系统能被业务信任的原因。
R13 与 `docs/spec/CURRENT.md` 的当前决议优先于任何通用 autonomy ladder；没有新登记决议，
不得把“可逆”解释为可自动审批、过账或执行。

LLM 计划助手真正能落地的，都做到了：**扎根于底层计划数据 + 强制引用 + 拒答模式 + 审计留痕。**
可解释性是硬约束，不是加分项。

## 六、主数据

可靠做法：主数据完整度**有分数、有责任人、有闸门**；缺少决策必需字段时，建议应留白、
降级或进入复核，而不是伪造默认事实。
风险信号：把主数据治理当成导入时清洗一次的动作，之后不再测量覆盖、冲突和新鲜度。

本系统：`report/data-health.ts` 按 skuType 裁剪适用维度评分，另有结构性告警（BOM 嵌套）。

## 七、渠道与口径

成熟的 S&OP/IBP 产出的是**一个达成共识的计划**，用量和钱两种口径表达，
且把需求计划与财务目标之间的**缺口显式量化并指派责任人**，而不是硬压成零。

这恰好是本系统 refGap 的做法：不假装系统口径就是全公司口径，
而是把差量标出来、给原因、给责任动作。**保持这个习惯。**

消费品牌应基于**售出（sell-through）与渠道库存**做计划，而不是自己的发货（sell-in）。
本系统的销售真相源是聚水潭（电商实际出库），方向正确。

中国「一盘货」四层共享库存模型：**账实分离**（物理 vs 逻辑库存）、
共享策略（比例共享/区域共享/滞销强制共享）、渠道**预占**（预售与大促）。
项目仓网的当前数量与类型会变化；设计判断应读取当前主档与 `docs/NOW.md` 证据，而不是沿用旧计数。
