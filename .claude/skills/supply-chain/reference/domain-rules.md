## 一、这是什么系统

多品牌消费品（含美妆护肤）公司，成品、物料、仓网与渠道规模会随导入和主档治理变化。
当前规模、覆盖与数据缺口只从 `docs/NOW.md` 及其链接的证据取得，不在本页固化。

**为什么做**（每次做取舍时回到这三类问题，当前基线以 live authority 为准）：
1. 对账耗时和人力过高；
2. 委外结算公式曾被反例证伪；
3. 价格缺少受控变更。

**MVP 1.0 只做委外生产闭环**：BH→WO→PO/JG→FL→SH+QC→入库→JS，
库存实时记账、错账红字冲销、每日与聚水潭对账。
外部系统**对接而非重建**：聚水潭＝电商销售真相源，用友＝财务 ERP。

**角色**：运营（发起 BH）/ 采购 / 仓管 / PMC（生产计划，枢纽角色）/ 财务 / 管理员；
品控会签供应商准入。同角色内 `is_approver=true` 者为审批人。

## 二、R 规则（R1–R17）

| # | 名称 | 要点（违反即错账） |
|---|---|---|
| R1 | 价格异动 | 比价口径＝**基础单位＋未税**；基准＝该供应商该 SKU 最近一次终审 PO 价 → 价目表 → 首购免检。\|偏差\|>3%（D4）强制走 PC 变更单并选生效范围。**基准只在 PO 终审时更新，不在 PC 审批时更新**（防未执行价污染基准）。硬门，不可绕。 |
| R2 | 损耗容差 | 唯一来源＝`sys_params` 品类容差（包材 5% 会议定死，原料 2% 缺省）。**BOM 上的计划损耗率永远不参与结算**。 |
| R3 | SPU/SKU 归集 | 每个 SKU 必属且只属一个 SPU；报表默认 SPU 粒度，可下钻 SKU。 |
| R4 | 库存账务 | 自有仓＝实时**追加式**台账；快照仓（保税/E仓/云仓）＝`stock_snapshots` 独立表、按日覆盖、**绝不进 `stock_balances`**；自有仓→快照仓经「调拨在途」虚拟仓 + 到货核销。**委外仓允许负数**（＝垫料，对账页标红）；其余自有仓禁止负库存。在途＝已审批 PO 未收量（仅实物行）。 |
| R5 | 委外结算逐物料 | 旗舰规则。有效完工数 Q＝合格+让步+备品。逐物料：净标准＝BOM用量×Q；允许损耗＝净标准×品类容差；实际损耗＝累计发料−累计退料(TL)−净标准；超额＝max(0, 实际−允许)。**禁止跨物料轧差**（量纲不同）。扣款＝超额×当月加权均价。应付加工费＝Σ 按收货时点分段(合格数×当时JG现价) + 让步数×让步单价；备品免加工费。JS 审批触发损耗核销过账，**过账后该 JG 的委外仓余额必须＝0**（有残余须 TL 或书面说明）——防同一笔损耗被重复扣款。 |
| R6 | 供应商评分 | **已被 D7 取代**：质量40/交付40/价格20，季度。01 文档里的「准交40/质量40/配合20」已过期。红线→黑名单硬门。 |
| R7 | 对冲池 | 备品/损耗/补送按当月加权均价入 `offset_pools`；季度盘点后一次性清算调整单。 |
| R8 | 编号 | `doc_counters(prefix, biz_date, last_no)` 原子 upsert + `UNIQUE(doc_no)` 兜底。**禁止 MAX+1**。SKU 主码＝现行商家编码（D10；旧「品类2位+5位」已作废）；SPU＝P+5位。 |
| R9 | 脱敏 | 黑名单＝成本价/采购价/合同价/加工费单价/结算金额/扣款单价/银行账户/税率。运营+仓管**永不可见**；PMC/采购/财务可见。唯一收口＝`src/server/core/dto.ts` 的 `maskSensitive`，覆盖 RSC/路由/导出/报表。**前端隐藏不算数。** |
| R10 | 并发 | 乐观锁 + 幂等键；**幂等命中优先于版本冲突**。过账 `UNIQUE(source_doc_type, source_doc_id, source_line_id, action, warehouse_id)` 硬约束防重复过账。余额更新按 (skuId, warehouseId, batchId) 排序防死锁。 |
| R11 | 净需求/补货 | 建议量＝毛需求 − 可用库存 − 在途，向上取整到 MOQ/订货倍数；三个数并排展示，采购确认。**产出是 BH 草稿，永不自动开 PO。** |
| R12 | 红字更正 | 已审批单据一律经**红字冲销**（引用原单的负行 + 审批 + 全留痕）纠错，再重开正确单。**反审批已废除**。红字 ≠ 作废（作废＝单据从未生效）。原单不可二次冲销。 |
| R13 | 双义 | (1) 指标：可销天数 DoS＝(在库+在途)÷近三月日均销；(2) **教义：守护式自动化/人工闸**——自动化只产**草稿**，审批永远是人；驾驶舱洞察「仅陈述不开单」。这是当前项目对通用 autonomy 模型的上位约束；没有 `docs/spec/CURRENT.md` 的新决议，不得扩大自动执行。 |
| R14 | 滞销判定 | DoS 超阈值（0.35/0.11，`sys_params` 参数化）→ 滞销清单 + 库存金额占比板。 |
| R15 | 效期分层 | 7 段互斥左闭右开：已到期 / (0,3月] / (3,6月] / (6,12月] / (12,18月] / (18,24月] / >24月。载体＝`batch_stocks` 参考层。 |
| R16 | 借调追踪 | 借调＝逻辑仓调拨 + `stock_docs.reason='借调'`（行上无渠道字段）；月末自动借调对账。普通调拨不计入。 |
| R17 | 调拨不计销售达成 | 调拨只有数量没有金额；销售达成率**排除调拨出库**。任何「出库→销售」聚合必须排除 `subtype=transfer`。 |

## 三、三层口径纪律（系统级红线）

这是本系统最容易被违反、违反后最难发现的一条。

| 层 | 载体 | 能否过账 | 用途 |
|---|---|---|---|
| **记账层** | `stock_balances` / `stock_ledger` | ✅ 唯一可过账 | 自有实时仓，追加式，红字冲销纠错 |
| **快照层** | `stock_snapshots` | ❌ | 保税/E仓/云仓，按日覆盖，**必须显示数据龄** |
| **参考层** | `transit_refs` / `batch_stocks` | ❌ 永不 | 只影响建议与标签 |

**参考层铁律**：`有效在库 = max(系统在库, 全口径参考)`——**参考只能调高认知，绝不调低**。
参考层不可当账。

### 覆盖缺口（refGap）

系统口径与全公司口径可能覆盖不同仓群；差异须先分类为覆盖、时点、映射或账务问题，
不能自动当成零，也不能直接判成错账。当前覆盖数量与样本见 `docs/NOW.md` 链接的最新血缘证据。

处理：全管道充足的缺口 SKU → **抑制建议**，但 **抑制 ≠ 隐藏**——
必须逐行给出抑制原因 + 页面级计数 + 参考数据时间戳，人工核实后仍可手工开单。
历史样本证明覆盖缺口会制造大量误报；引用任何数量前必须在当前 revision、数据截止日和范围重算。

代码：`src/server/rules/fusion.ts`（`fuseCover` / `detectRefGap` / `shouldSuppressSuggest`）。

## 四、单据流与前缀

```
BH 备货申请 ──→ WO 委外工单 ──┬─→ PO 采购订单（仅原料/包材行）
（运营发起）    （wo_line 是      │    加工费永不作为 PO 行
                 审批时的 BOM     │    JS 是应付的唯一载体（防双重应付）
                 快照，此后改      │
                 BOM 不影响本单）  └─→ JG 委外加工通知（携带加工费现价＝结算价来源）
                                        │
                          FL 发料（自有−/委外+）
                                        │
                          TL 委外退料（R5「退回量」的唯一数据源）
                                        │
                          SH 收货（行类型：正常 / 返工重交 / 备品）
                                        │
                          QC 检验（合格 / 不合格 / 让步）
                            不合格三条路：退厂返工TL重交 / 让步(审批价) / 报废(红字)
                                        │
                          JS 委外结算（与 JG 1:1，收货关闭/短关后）
```

其余：`PC` 价格变更 · `CT` 采购退货（库存−，PO 已收数回冲）·
`RK/CK/DB` ＝同一张 `stock_docs` 表的入库/出库/调拨三个前缀 ·
`PD` 盘点（定期全盘/抽盘——**抽盘就是 PRD 说的「永续盘点」**）·
`CA` ＝盘点审批事务生成的差异调整单。

**状态机**：草稿→待审批→已审批→[PO/JG 确认代录]→执行中→已完成；
支持短关（可重开）；作废级联矩阵（WO 作废 → 未执行的 PO/JG 自动作废；已部分执行 → 短关 + TL）。

**进度标签（11 态）只由单据事实推导，禁止手填。** 历史例外走 `migration_opening` 事实。

## 五、审批域（SoD 系统强制：审批人 ≠ 制单人）

| 单据 | 审批域 |
|---|---|
| BH 备货 | PMC |
| WO 工单 / BOM 生效 | PMC 审批人且非本人 |
| PO / PC | 采购审批人 |
| FL / TL / SH / CT / 调拨 / 出入库 / 红字 | 仓管审批人 |
| **期初（opening）** | **财务** ← 易错：不要并回 stock_doc 域 |
| **盘点（count）** | **财务** |
| JS 结算 / 让步单价 | 财务 |

BOM 批量生效：每个导入批次一次审批（PMC 审批人 ≠ 导入操作人）+ 10% 抽检。

审批幂等键**含 cycle（单据版本）**——驳回→重提→再驳回属新轮次，否则被幂等短路。

## 六、生命周期状态

**SKU**（4 态，取代布尔 active）：在售 / 试销 / 停售 / 淘汰。
- 停售：禁新 BH/WO/PO 行，但允许移动
- 淘汰：只允许退货/报废/盘点
- 试销：报表打标

**供应商**：当前批准的状态与转换只从 `docs/spec/CURRENT.md` 取得；D38 的目标词汇为
pending→qualified→paused→blacklisted→retired，但实现/迁移状态必须另查 schema 与当前 revision。
通用行业阶段只能映射到这些状态，不能擅自新增枚举。准入＝采购初评 + 品控会签；
**黑名单＝新 PO/WO 硬门**；重入条件以当前决议为准。

## 七、数据摄取纪律

```
适配器 → staging_rows → 校验 → 复核工作台（人工闸）→ 既有审批+过账 → 正式库
```

- **别名优先**：`aliases` 表 `UNIQUE(aliasType, rawValue)`，类型 ∈ warehouse/channel/sku_code/sku_barcode/supplier_oem/brand。碰撞 → `alias_exceptions` 标「歧义码」，**认领前禁止解析**；认领后重放行会提交此前被挡的行。
- **清洁摄取**：只导入长表；所有宽表透视一律用视图重建，**永不导入**。
- **双通道解析**：exceljs 优先，自动回退原始 OOXML（三个最高价值文件让 exceljs 崩过）；逐文件解析行数须在复核基线 ±0.5% 内，否则拒绝。
- **绝不猜**：BOM 同名多块无文字标记 → **100% 人工裁决**（新变体 vs 旧版本停用）。启发式自动生效被**禁止**——判错会污染 wo_line 快照与结算基数。
- **不伪造历史**：存量单走新旧划断（D16）；例外经 PMC 审批后走 `migration_opening` 过账子类。
- **幂等**：重导用 superseded 机制；快照/汇总模板按 (template + bizDate) 覆盖；主数据按编码 upsert。
  历史重放规模不是当前保证，引用前须重测。
- **新鲜度看门狗**（`src/jobs/freshness.ts`）：stock_summary/fg_order 7 天、pallet/demand 40 天、月销 45 天超期自动开复核项，重传自动关闭。

## 九、UAT / 平行运行纪律（`docs/spec/07-UAT场景矩阵与并行运行手册.md`）

- **入场**：全量测试绿；staging 期初迁移演练仓管签字；5 个角色账号 + 分角色培训。
- **出场**：41 个场景（31 核心 + 10 新增）通过或书面豁免；S1/S2＝0；S3 有修复排期；财务+PMC+运营三方签字。
- **缺陷分级**：S1＝错账/权限穿透/系统不可用；S2＝主流程阻断无绕行；S3＝有绕行；S4＝观感。每次修复→全量回归。
- **场景风格**：★ 异常路径全部来自红队实证（重提后再驳回、含税/未税混价、超发、超退、红字二次冲销拦截、库存不足 409 且不留审批残留、结算残余 409 闸）。
- **平行运行**：系统为准，旧流程（用友+Excel）影随记录**不停**；每日 15 分钟分角色检查单。
- **中止阈值**（冻结系统入口并升级）：1 个 S1；或自有仓对账差 >3% 连续两日；或任一角色检查单连续三日无法完成。
- **DoD 对账门**：|系统出库−聚水潭|÷聚水潭 ≤1%，逐 SKU 逐日，**连续 14 天**，财务签字。
