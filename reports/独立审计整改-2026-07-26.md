# 独立审计整改记录（2026-07-26）

## 结论

本轮按“先证实、再修复；不把外部依赖伪装成已完成”的原则完成。高风险缺陷已修，
批次能力已形成端到端代码链但默认关闭，外部连接器只登记真实就绪度，不宣称已接通。

## 已完成

1. **供应商编辑不再清空财务/联系字段**
   - 通用 CRUD 编辑支持先取详情；
   - 供应商详情 GET 返回完整字段并按角色脱敏；
   - 编辑表单不再从缺列的列表行直接回填。
2. **仓库编辑不再清空 `parentId`**
   - 仓库详情 GET + 上级仓字段；
   - 服务端拒绝自指、下级反挂与既有环。
3. **种子账号拒绝公开默认密码**
   - `SEED_ADMIN_PASSWORD` 必填且至少 12 位；
   - 只影响新种子执行，既有账号仍需人工轮换。
4. **React 19 / AntD 5 兼容**
   - 因当前环境无法联网安装 `@ant-design/v5-patch-for-react-19`，
     使用 Ant Design 官方等价 `unstableSetRender + createRoot` 接法。
5. **快照放行改为明确、可证明的一次性发布**
   - 每次必须选择且只能选择一个导入任务；
   - 预演摘要 SHA-256 绑定任务、文件、业务日、规则版本与行内容；
   - 执行必须携带同一摘要，输入变化即拒绝；
   - 源拒收、解析阻塞或行数不平时拒绝部分放行；
   - 零库存显式落零，不残留旧快照；
   - 记录来源任务、业务时点、范围、控制总量、发布清单；
   - 原子认领发布权，重复/并发执行最多成功一次。
6. **QC 完整性**
   - 每个收货行必须且只能提交一次 QC；
   - 合格+不合格+让步必须精确等于实收；
   - 备品只按 QC 合格+让步数量入库，失败备品不再混入可用库存。
7. **批次/FEFO 端到端代码链**
   - 收货、发料、退料、采购退货、手工出库/调拨均可贯通 `batchId`；
   - 自动 FEFO 按 SKU 汇总后稳定拆回业务行；
   - 显式批次校验 SKU 归属、效期与余额；
   - 过期批次从可发分配中排除，不再“提示后仍优先推荐”；
   - 历史无批次余额仍有显式迁移回落，避免死库存；
   - 运行参数 `batch_posting_enabled` 默认 **0**。
8. **计划任务唯一权威**
   - PostgreSQL 只启 `pg-boss`；PGlite 只启 interval 回退；
   - durable scheduler 覆盖完整九项任务，不再只接三项；
   - 进程内和数据库层各自防重复启动/抢占。
9. **供应商确认 token 原子消费**
   - token 使用改为条件更新；
   - 并发请求最多一个成功；
   - 逐行越权/不存在会回滚 token、表头、行与审计。
10. **外部连接器不再是不可见空数组**
    - 聚水潭、用友、飞书进入统一目录；
    - “代码实现”“凭据配置”“实际可运行”分开判定；
    - 管理员运维页展示阻塞原因；
    - 聚水潭/用友仍为 `contract_only`，不会被运行任务误认成已接通。
11. **开发库备份/恢复护栏纠偏**
    - 修正备份脚本检查错 writer-lock 路径的问题；
    - 对单写者闸上线前启动、没有锁文件的旧进程增加 `lsof` 二次拒绝；
    - 恢复演练只消费停机归档，不再复制 live `.data/dev`；
    - 恢复前校验归档路径，原库按时间戳保留，不自动删除；
    - smoke 脚本不再回落到公开 `admin123`。

## 默认关闭 / 不可直接宣称上线

### 批次过账

代码完成不等于允许开闸。启用前必须：

1. 在可恢复的数据库上应用迁移 `0019`、`0020`；
2. 对现有 `batchId=null` 余额形成迁移/盘点清单；
3. 用真实 SH→FL→TL/CT→库存出库/调拨场景完成 UAT；
4. 核对过期、无效期、历史回落和并发超扣；
5. 由管理员把 `batch_posting_enabled` 从 0 改为 1；
6. 首周每日核对批次余额合计与 SKU×仓总余额。

### 外部连接器

- 聚水潭：缺 API 凭据、租户信息、字段/限流/增量契约；
- 用友：除凭据外还依赖成本口径 D2；
- 飞书：代码已接通，仍需 `FEISHU_WEBHOOK_URL`。

### 数据库

本轮未启动或修复损坏的 dev 数据库，也未运行 `pg_resetwal`。迁移只在全新 PGlite
测试库完成重放验证；dev/staging 的实际迁移须在恢复决策完成后执行。

## 有意不建设

- 不新建第二套库存台账、微服务群或大而全“Inventory Truth”平台；
- 不为当前 6–8 个种子用户先造完整 IBP 治理组织、能力策略平面；
- 不重复建设指标注册表（项目已有 `metrics.ts`）；
- 不把缺凭据的连接器包装成“已配置即已运行”；
- 不自动打开会改变库存维度的批次闸门。

这些不是漏做，而是独立红队后保留的范围边界。扩建条件应是实际用户、数据量、
组织协同或合规要求已经出现，而不是架构想象。
