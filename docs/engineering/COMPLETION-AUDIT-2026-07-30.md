## 1. 总体结论

- 会议 P0 与 SKU 前向标准已实现并经受保护 PR 合并。
- 202 项去重能力中 193 项完成、4 项部分、5 项因真实事实或外部授权阻塞。后续红队发现并关闭
  一项隐藏代码缺口：原物料需求只展开一层，会把有下级 BOM 的半成品误作末级物料。
  现已改为多层递归、逐层损耗，并在 BOM 生效事务内从全部受影响根阻断循环/异常深度；
  WO 审批也冻结末级原料/包材，未完成的半成品链不能进入 PO 生成路径。
- 剩余工作不能通过继续写占位代码诚实完成：它需要业务分类、真实试点、销售/成本/活动事实，
  或聚水潭/飞书/用友企业机器授权和 UAT。
- 精益审计没有发现内容完全相同的测试文件；当前本地全量 1,762 项约 53 秒，日常窄门约 7 秒。
  GitHub 全量任务的安装仅约 19 秒，主要耗时是托管运行器执行数据库密集套件。删除独立业务
  不变量不会显著加速，只会降低发布可信度。

## 3. SKU 编码方案审计

结论：S1 适合当前阶段，且比延续旧品牌/产品族/物料段拼码更稳健。

`S1-{来源}-{类型}-{六位全局流水}-{两位校验码}`

- 只编码稳定起源、类型和企业全局身份；渠道、供应商、规格、生命周期和 BOM 父项保持结构化。
- 全局流水由 `doc_counters(prefix='SKU-S1', bizDate='GLOBAL')` 在保存事务内原子分配。
- `000000`、格式错误、CRC 错误和人工占用 `S1-` 均被拒绝；碰撞继续取号。
- 已生成 S1 的稳定来源/类型不可漂移；全部旧码、外部码和别名继续兼容，不做破坏性批量换码。
- 人员参考、字段解释和操作示例见 [`../spec/19-SKU编码标准-S1.md`](../spec/19-SKU编码标准-S1.md)。
- S1 的来源段直接区分品牌；共享物料使用 `GEN`。GTIN、各包装层级条码、聚水潭/用友、
  供应商/客户和历史编码已拆入 `sku_identifiers`，带 GS1 校验、作用域、唯一约束、审计和 UI。
- 历史唯一条码由迁移保守登记为 `legacy`；重复条码不猜归属，仍需业务裁决。
- GTIN/legacy 同值认领现使用同一事务锁串行化；BOM 命中同 SKU 的既有有效单品 GTIN 时，
  会幂等补齐主标识与兼容条码，而不是把缺失主标识误判为无需处理。
- `data:audit` 新增不含原始标识值的 SKU 身份控制：当前 5,376 个历史 SKU 尚无 S1，
  682 条 legacy 标识无精确键重复；5 个重复条码归属组和 1 个畸形值继续留给人工裁决。

## 4. 外部系统与安全边界

| 系统 | 代码侧完成 | 外部必须提供 |
|---|---|---|
| 聚水潭 | 签名、游标、退避、批次证据、库存增量观察、staging、checkpoint、对账与调度 | 企业 app/token、IP 白名单、接口权限、责任人、真实控制总量与 7 天恢复 UAT |
| 简道云 | 9 应用/297 表单目录；九条字段最小化契约；schema 漂移、PII、重复视图、重放、checkpoint 与 releaseBlocked staging 闸 | 轮换已暴露 API/MCP token；裁决重复视图；逐契约控制总量、crosswalk 与 UAT；现有源数据主要停在 2023–2024 |
| 飞书 | 应用机器人、token 缓存、UUID 去重、webhook 回退、数据库发送租约 | app/chat 或 webhook 机器配置、目标测试群、权限与投递/失败恢复 UAT |
| 用友 | 目标企业 YonBIP、专用已启用 AK/SK、八条只读优先契约、C4 allowlist/base URL、系统边界与 readiness 状态 | 租户/目标组织 ID、token URL、企业授权范围、只读沙箱对账与 UAT；门户/AK/SK 不能单独构成 live |

人工网页登录口令不是服务器 API 凭据，不写入仓库、文档、日志或部署配置。

简道云 MCP 只可作为个人辅助查询入口，不进入服务器后台同步；系统集成唯一使用最小权限
OpenAPI key。重复 `entry_id` 在不同 app view 中会出现不同字段/行数，故任何聚合必须绑定
`app_id + entry_id + data_id` 并指定唯一权威视图，禁止跨 app 相加。

## 5. 精益、重构与测试红队

- 保留模块化单体；当前负载没有支持微服务、微前端或第二库存/指标平台的证据。
- standalone 构建排除本地数据、备份、上传和恢复证据，并在构建后扫描敏感路径。
- 旧 `.next`、`.next-live` 和验证输出已可恢复地移出工作区；约 2.5 GiB 可再生产物被清理，
  `.data`、`backups`、`uploads` 和迁移历史保留。
- 222 个测试文件没有 SHA-256 完全重复；526 项执行审计中的逐项断言约 49 ms。
- 40 个迁移已在本地真实 PostgreSQL 16 应用；发布合约显式验证
  `sku_identifiers` 表、GTIN/作用域约束、全局唯一性与主标识索引。
- 本地快速门用于编辑循环，全量测试只在 PR/发布边界运行。未采用更多 CI 分片，因为它增加
  运行器开销和拓扑复杂度，且尚无净收益测量。
- 两个 live-authority 文档中的历史“当前状态”和旧会话交接已归档，避免过期信息继续驱动实现。

## 6. 仍需完成的真实出口

1. 业务确认 7 月末样品/赠品/试用/内用清单并走受控分类。
2. 指定两个试点产品和业务、供应链、财务三类真实用户，完成 41 场景 UAT/缺陷闭环。
3. 裁决 operational alias/条码所有权、剩余物料编码与品牌缺失；补海外仓/其他部门覆盖。
4. 提供售价、促销/活动、销售承诺、渠道优先级、最终成本/资金成本和足够 NPD 日事实，
   才能诚实点亮毛利、促销 lift、ATP、fair-share、EOQ 与上市爬坡。
5. 企业管理员完成各外部系统机器授权与密钥库配置；简道云先轮换 token 并裁决重复视图，
   飞书提供 API 可见 chat_id，用友补齐租户/组织/端点/服务授权，再做控制总量、恢复演练和上线签字。
6. 在生产环境轮换曾可能进入旧镜像层的历史签名密钥；不得把新值发到聊天或提交到 Git。

这些出口是数据、权限和组织验收，不是可由本地代码猜测或代替的工程缺陷。
