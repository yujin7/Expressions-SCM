# 新品写安全与恢复验收

## 用户流程与不变边界

运营/计划进入准确项目，推进节点或补目标SKU，生成首单BH草稿，核对后进入既有审批。网络失败/刷新时能找回同一次请求，不因为反复点击产生重复草稿；多人操作不得覆盖已变化的项目。关闭是项目管理状态，不等于节点完成、订单审批、质检、入库或新品商业成功。

## 实现

- 聚合版本：所有项目写入先锁项目行，再读取/修改节点；版本不符409。只读详情用一致快照，不阻塞写者。
- 状态：完成/取消保留事实，普通写入拒绝；显式恢复不重建节点或订单。相同完成状态不改历史doneAt，省略note保留、空字符串明确清除。
- 首单：复用createBh事务与doc_counters；BH、明细、NPD关系、版本、两端审计同事务。数量采用BH十进制契约并规范成四位小数。
- 请求：操作者+UUID唯一，同键不同项目/版本/数量409；相同请求在项目后续变更或关闭后仍可读取原BH，但必须仍有写角色和BH读取范围。新UUID加最新版本可以明确另起一张草稿。
- 迁移0061：新增npd_projects.version及npd_first_orders，外键、唯一与正数量/版本检查；手写update/delete/truncate拒绝触发器保留，不得被重新生成迁移吞掉。无历史猜测回填。
- 浏览器：账号+项目隔离的最小localStorage记录；持久化失败先于POST停止。响应20秒限时、网络失败/非法响应均保留原请求；不自动重试。迟到成功不删除较新请求。只清本机记录不声称撤销服务端单据。
- 项目关联记录复用BH范围，在LIMIT前过滤；显示最近20条可见记录、状态、生成数量和基础单位，精确链接到BH。
- HTTP首次生成201，确定重放200，内容/版本冲突409；每次写重新查询会话。旧页面没有version/requestKey时拒绝，不保留不安全的兼容写口。
