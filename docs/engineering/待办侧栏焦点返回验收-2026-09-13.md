## 为什么这样修

检查已安装rc-drawer发现：焦点归还依赖关闭动画完成；本页以条件渲染直接卸载侧栏，该回调不会执行。改派又从短暂菜单发起，不能把消失的菜单项当成返回点。

[W3C弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)建议关闭后返回触发元素；触发元素不存在时转到合理的后续位置。本轮不升级UI库或全局覆写Drawer，而在拥有侧栏的父组件显式记录真正的按钮，使用一个44行共享hook。

| 情况 | 返回行为 |
|---|---|
| 新建或恢复创建关闭 | 原“新建待办/恢复待办创建”按钮 |
| 跟进记录关闭 | 同一待办的“跟进记录”按钮 |
| 改派关闭 | 同一待办的“更多”按钮，不返回短暂菜单项 |
| 桌面/手机切换、列表重建 | 若原按钮隐藏或断开，按同一任务+操作找当前可见按钮 |
| 原任务移出筛选、按钮禁用 | 返回带名称的当前列表，不猜测下一行身份 |
| 恢复提示清空或原入口消失 | 有结果时保留在恢复说明；零面积空区域则返回待办工作区 |
| 接续另一个侧栏、用户已有新焦点 | 不抢回旧位置；离页/卸载/快速重开取消延迟回调 |

接口权限、原请求编号/版本、忙碌关闭限制、原回执核对和数据副作用均沿用原实现。没有增加派工政策或改D70。React审查采用refs保存暂态焦点、限定依赖和关闭时单次回调，没有新全局事件监听、数据请求、状态缓存或UI依赖。
