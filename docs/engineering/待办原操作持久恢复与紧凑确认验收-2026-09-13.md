## 完成的用户闭环

| 情况 | 实际行为 |
|---|---|
| 点击完成、开始、取消、重开或改派 | 先按站点/账号保存有限原请求，含待办ID、所见版本、UUID和原意；持有跨标签Web Lock，未核对请求不能被下一次点击覆盖 |
| 服务器保存但页面丢回复 | 保留原记录，错误附近及待办页独立入口均可恢复；刷新/筛选/任务后来关闭不自动再写 |
| 核对原操作 | GET严格核对原键、待办、原意和结果；原回执与当前任务分开显示，不把后来重开/改派误说成当时结果 |
| 暂无回执、版本相同 | 不推断“没有执行”；只能继续核对或明确重试原键/版本/内容，重试前再GET |
| 暂无回执、版本已前进 | 旧版本已不能执行；重新GET确认后可明确清理本机记录，不再次PATCH |
| 确认已有回执 | 重新GET核对同一原回执，再只清匹配本机键，提供准确待办链接 |
| 存储损坏/不可用、响应异常或撤离页面 | 明确未知且保留证据；存储不能写则不发送。迟到回包不能清掉离开页面的原请求或更新另一账号界面 |
| 页面提示 | 结果/失败出现后焦点回到可见内容；侧栏宽度限制在当前视口，核对清理后旧错误入口消失，新操作不复用上一笔确认提示 |

保留原状态机、当前权限/范围、不可变审计及来源独立性，不关闭来源告警、不写库存、不改D70派工裁决。本机有限副本不含密码或会话；不是跨设备恢复，也不等于服务端取消。
