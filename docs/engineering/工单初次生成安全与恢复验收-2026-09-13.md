## 修复及边界

| 原问题 | 现在的行为 |
|---|---|
| 生成资格/已有JG在事务外读取，仅信任调用方角色 | 事务内回查当前账号、角色和会话版本；锁目标WO后核对状态、已有JG；供应商/物料/成品共享锁保持资格至提交 |
| 初次生成和自动分批可能同时通过检查，最后碰唯一约束 | 共用WO锁，已生成返回409，不靠唯一约束异常冒充业务冲突；保留`UNIQUE(woId,batchSeq)`，不改成每WO只能一批 |
| 只核对PO分组供应商，漏掉WO加工厂 | 无PO或材料供应商与加工厂不同，也核对加工厂暂停/黑名单 |
| 输入可超工单量或舍入成零/数据库溢出 | JG不得超过已审批WO量且必须正数；数量/换算、价格、税率按现有字段精度拒绝，零写入 |
| 零建议采购量自动回填毛需求 | 只预填正建议，四位小数字符串保留；零建议可只生成JG；允许人工明确添加/调整采购，不擅自按建议量硬封顶 |
| 校验等待期间可重复点，空分组被静默丢弃 | 同步提交锁、绑定来源ID、空分组明确报错；页面离开/切换不产生错源提交或过期刷新 |
| 失败只闪一条提示；生成成功只有单号 | 持续显示来源和错误，先刷新核对再重试；成功明确是未提交草稿，准确链接PO/JG，导航时关闭回执 |
| 弹窗被详情抽屉覆盖、手机输入框越过卡片 | 生成弹窗1100、回执1200；手机宽度约束和分组换行，详情长成品独占一行，避免数量被挤碎 |
| 选源请求可乱序覆盖新物料，失败仍像无记录 | 复用身份绑定GET：切换即撤旧、15秒超时、只读重试；未知不说首次寻源；关闭生成框不继续拉取选源事实 |

**初次生成仍是采购前的草稿流程**，不能误套“已经收齐材料才允许生成PO”的循环依赖。
不会自动审批、收货、移动库存或认领外部事实；PO数量/单价仍需业务人员核对并提交审批。
写路径技能促使本轮验证身份/状态/数量/整笔审计与并发；Next.js/React检查复用现有读取边界、
在渲染时派生物料身份，不引入服务端值依赖、重复读取框架、新依赖、迁移或第八个技能。
