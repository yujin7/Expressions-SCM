## 修复及边界

| 原缺口 | 当前行为 |
|---|---|
| 收口请求结果不明，用户只能再点一次 | 提交前保存账号+单据隔离的最小核对标记；超时、响应格式异常、POST后GET失败不自动重发，明确先核对 |
| 刷新后单据已终态，原动作消失连带隐藏恢复 | 共享组件放在PO/WO详情正文，不依赖终态动作栏；已关闭/已完成仍保留待核对入口 |
| 重复点击、另一标签或迟到响应覆盖状态 | 同步锁拦重复点击；相关storage事件同步待核对；按token清除，不能清除更新标记；换账号/单据重新挂载，卸载或撤权不触发迟到成功回调 |
| 确认框打开后借用新版本提交 | 绑定打开时版本，版本改变先拒绝提交并要求核对；等待时不能关闭确认框 |
| 短关后原因不可见 | PO/WO详情返回并显示closedReason；读取校验准确ID、单号类型、状态、版本及原因字段，使用当前身份和private/no-store |
| 工单提示误称会自动短关关联单 | 明确只停止本工单，关联PO/JG另行核对；采购完成/短关不补收货、不修改已收数量、不改库存事实 |
| PO收口使用旧角色且未锁单 | 同事务回查启用、会话与角色并锁PO；状态/版本/原因/审计原子写入；竞争串行，重复目标状态不覆写原原因或增加审计 |
| 错误提示被长内容藏住 | 确认框正文独立滚动、底部动作保留；正文恢复区按钮可换行，390px实测无整页横向溢出 |

标记仅含UUID、动作、版本，**不是服务端成功回执**，不保存短关原因、费用或凭证。读取到当前状态也不能证明原请求执行或未执行；用户明确确认后刷新详情，再决定下一步。服务端仍沿用现有“目标状态已达成”重放语义，不冒称账号绑定的不可变收口回执或跨设备恰好一次。损坏存储在GET成功后也继续阻止新写；统一自助修复/跨设备对账尚未实现。
