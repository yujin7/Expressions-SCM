# 单据读取与紧凑详情复核

基线4370558，原工作区173路径保留；所有浏览器数据来自隔离QA，不改3100、真实凭据/数据/授权。

## 用户任务与根因

从列表找到单据→打开当前事实→读取简报/链路→选择允许的来源操作→返回列表。快速切换或失败不能留下上一张单据的事实及动作。

原ApprovalBrief换docId不清旧数据、无取消/超时、失败标记不会恢复；ChainStrip错误静默，与无关联不可区分。BH列表/详情请求无乱序保护；载入新详情时旧动作仍可见。8个行为反例先红，随后扩展到14项，包括关闭重开同ID、刷新、取消、迟到成功/失败、超时、畸形响应和重试。

## 实施

- 共享useDocumentRead只管理GET：以URL/重试轮次绑定身份，切换/刷新立即撤下旧数据，清理时取消请求，15秒超时后允许手动重试。不缓存、不自动重试，不处理写事务。
- BH列表/详情及共享审批简报/链路采用该生命周期；详情失败有持久重试，辅助资料不可用不伪装成健康，不改变服务端审批规则。
- DocumentDrawer先覆盖BH/PO两个消费者：标题与动作窄屏分行；主信息窄屏单列、标签不拆字；宽表局部横向滚动。
- 浏览器人工检查发现PO宽表曾推动整个抽屉横移，补scroll.x，并增加抽屉body无横向溢出的验收条件。没有用全局overflow:hidden掩盖。
