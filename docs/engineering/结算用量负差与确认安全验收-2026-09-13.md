## 修复的真实风险

R5 的实际损耗是 **发料 − 退料 − 标准用量**。发料99、退料0、标准100得到−1；再退1会得到−2，不会消除差异。旧预览、详情、审批错误及财务工作台把负值解释为“实物结余未退”，可能引导错误退料。

现在统一表述为“净发料低于标准用量 / 用量负差待核对”：先核对发料、退料、产出、单位、BOM及差异原因。有原单错误先驳回纠正；实际节约也须有核对依据。负差既不证明现场余料，也不证明应补发或账实相符。

| 范围 | 当前约束 |
|---|---|
| 预览、明细、提示、审批弹窗 | 说明负差的真实含义，不再要求先退料；正损耗、扣款及允许损耗公式未改 |
| 财务工作台 | 显示“用量负差待核对”，准确进入 `/settlement/js?status=pending`；计数仍为存在负差的待审单据数 |
| 特殊确认触发 | 只接受结构化409及 `SURPLUS_UNACKED`，不从任意错误文字猜测；403、其他409、500、网络错误不得触发 |
| 确认对象 | 绑定单据ID和版本，必须仍有当前批准资格；换单撤销旧确认，重新触发清空勾选/说明，忙碌写入不丢失确认 |
| 传输及兼容 | `JsonRequestError`只保留现有安全短消息、HTTP状态和有限格式错误码，不附带原始响应。`acknowledgeSurplus`、`surplusNote`、`SURPLUS_UNACKED`、`surplusMaterials`、`jsSurplusUnacked`保留为既有接口/审计兼容名，不再按英文旧名推导业务含义 |
| 库存/财务安全 | 确认说明仍必填；后端当前身份、职责分离、版本、JG锁、依据和期间校验不变；只对正实际损耗走既有核销，不补库存、不自动改历史金额 |

没有新增迁移、依赖、API路由、权限配置或第二套计算口径。
