## 修复的业务断点

既有结算只有加工费更新出口：物料发退数量、损耗和扣款依据变化后，缺少可核对的草稿恢复流程。结算须在JG完成/关闭后发起，而退料创建只接纳已审批/执行中JG，导致需要退余料时无法从页面创建。另有两个正确性风险：同一工单重复物料行重复消耗累计发退数；不同发退单并发批准未共同锁定JG，可能绕过累计数量守卫。

| 变化 | 当前边界 |
|---|---|
| 核对结算依据 | 显式打开才读取；并排展示已保存/当前收货数量、费用、扣款、手工调整和结算金额，另列逐物料依据和代理成本警告。GET不改写单据 |
| 更新草稿 | PMC/admin填写说明，携带准确单据版本及核对指纹；事务内复核当前身份、数据库渠道范围、草稿状态和当前计算。手工调整保持原值；替换草稿明细与审计同成同败，不产生库存流水 |
| 待审批/已冻结 | 待审批须先由合格审批人驳回，再核对更新并重提；已审批/完成仅对照，不静默重算、不改写历史金额。旧费用专用更新入口保持兼容 |
| 过期依据 | 提交/新批准核对保存依据与当前计算；发生差异明确拒绝。已完成准确轮次的重试保留幂等短路，不把重放变成重新计算 |
| 退料恢复 | JG已审批/执行中/已完成/已关闭可作为实物退料来源；筛选在服务端分页前执行。草稿、待审批、作废JG不开放。创建、提交、批准仍须原权限/职责分离、累计退料≤发料及实际库存守卫 |
| 并发 | FL/TL批准与JG/JS事务使用同一JG锁，先等待已提交发退事实再判断累计数量/结算依据。新FL批准仍限JG已审批/执行中；关闭后的合法驳回和已完成轮次重试不被新状态检查误挡 |
| 重复物料 | WO同SKU的qtyPer先按四位数量精度合并，再对该SKU使用一次累计发退数据，R5仍逐物料、无跨SKU抵扣 |
| 手机界面 | 汇总表三列自适应，数量复用格式化去掉无意义尾零；长数字允许换行。宽物料表保留内部横向滚动，不把整页撑宽 |

没有新增依赖或迁移，没有修改正式账号、密码、外部平台权限及正式业务数据。
