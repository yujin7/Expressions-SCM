## 修复的风险与业务边界

D33-b 是入库后的毛用量估算提示，与 R5 的标准净用量结算不同。旧实现把未完成SH的QC也计入，遗漏让步接收，同SKU多条WO行重复使用整笔发退料量；每种物料又各查两次数据库。旧提示把估算直接称为可退实物/必须补料，且没有可用的类别筛选与加工单回链。

| 范围 | 本轮实现 |
|---|---|
| 入库资格 | 仅准确JG来源、已完成SH；QC必须属于该SH与行，合格/让步/不合格非负且合计等于实收。计入合格+让步，包括实际接受的备品/返工；未过账不算入库 |
| 不完整依据 | 缺QC、产品不匹配、空收货行、缺/非法工单数量或毛用量，保留未知和核对原因，不把估算补成0 |
| 同SKU汇总 | WO毛需求、已完成FL、已完成TL各自先按SKU聚合，再关联；工单外实际发退物料仍显示，但毛用量未知；不跨物料轧差 |
| 精度 | `dMulDiv(入库量, 毛需求, 工单量, 4)`一次最终舍入，避免先除单耗或中间乘积舍入损失。复用原6位内部输入精度，不声称支持任意精度输入 |
| 查询与并发 | 来源事实用一条SQL快照；JG行锁串行本生产者，复核行锁保护人工处理竞争；当前仓管/admin身份在事务内重核，事项与审计同成同败 |
| 去重与变化 | 按准确JG及D33-b/v2事实指纹识别；相同当前依据不重复生成，已有open事项刷新但保留意见。人工已关闭的相同最新依据不重开；新依据另建待核对，不覆盖人的结论 |
| 零差额 | 现有待核对项更新为当前无差额，仍由负责人关闭；不自动认定账实一致。不批量删除旧重复项 |
| 可操作入口 | `material_leftover`正式进入已有类别过滤；“查看核对依据”按钮打开可滚动弹窗。新记录用JG数字ID准确回链，历史单号继续用原搜索入口 |

差额只是“净发料−毛用量估算”。它既不是实盘余额，也不能直接驱动TL/FL、补库存或解锁冻结结算。PMC核对计划/单位及后续需求，仓管核对原单和实物，冻结差额由财务核对纠错。没有新增迁移、API路由、依赖、角色权限或库存写入口。

选择单SQL而非多次独立读取，是因为PostgreSQL默认Read Committed下每条语句有自己的快照；多条SELECT可能看到不同时间的事实。本轮用单语句聚合、局部锁和真实并发测试，不扩大为全库隔离级别/重试架构变更。[事务隔离官方说明](https://www.postgresql.org/docs/current/transaction-iso.html)、[聚合函数官方说明](https://www.postgresql.org/docs/current/functions-aggregate.html)。这不保证其他所有历史来源修改者都使用同一锁。
