## 修复的实际断点

原来 SH 入库事务已提交，但后续物料估算 best-effort 异常被吞掉，用户没有持久入口区分“尚未计算”和“已算完”。再次入库不是恢复方式，会被已完成状态拒绝，也不应重放库存。

本轮复用已完成 SH 作为待处理依据，以同事务追加的 `material_review_checked` 审计作为计算成功回执；没有新增任务表、迁移或后台重试框架。

| 路径 | 当前行为 | 安全边界 |
|---|---|---|
| 正常入库后估算 | 返回 `materialReview: checked` 并保存 SH 计算回执 | 计算回执与复核事项创建/刷新在同一事务 |
| 入库成功、估算失败 | 保留已入库结果，返回 `pending`，显示恢复提示及结构化告警日志 | 不把已经提交的入库谎报失败，不记录原始异常中的敏感载荷 |
| 独立重算 | `POST /api/matflow/sh/[id]/material-review` | 新鲜会话/仓管或管理员，严格整数 ID，准确已完成 JG 来源；不调用库存过账 |
| 待计算列表 | `materialReviewPending=1`，URL 保留筛选，列表同单提示 | SQL 在计数/分页前排除已有匹配成功回执的 SH；非法参数拒绝而非静默忽略 |
| 重复或并发重算 | 一项当前指纹复核事项，每次成功计算各有审计 | 不重复入库、不覆盖人工已决事项、不自动关闭人工核对 |
| 手机端失败恢复 | 同一收货单内持久显示失败，保留上次成功时间，可安全重试 | 立即防双击；迟到响应不串到另一单；500/网络异常不再显示通用“勿重复提交”矛盾文案 |

`unknown`、`no_difference`、`needs_review` 是计算依据状态，不是人工验收结论。历史记录没有成功回执，只能说“可能未运行或失败”，不能断言曾经失败。上次计算时间是快照时点，不证明当前实物库存、负责人已复核或账实一致。未知也不伪装零差额。

延续上一轮单 SQL 事实读取与 JG/复核行锁，不提升全局隔离级别，也不假定其他写方都锁 JG。PostgreSQL Read Committed 每条语句取得自身快照，因此不能把多个读取天然当作同一时点。[官方事务隔离说明](https://www.postgresql.org/docs/current/transaction-iso.html)
