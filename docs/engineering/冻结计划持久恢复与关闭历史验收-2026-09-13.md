## 修复与安全契约

| 原问题 | 本轮行为 |
|---|---|
| 请求键仅存页面内存，刷新即丢 | 发送前按当前账号保存有限周期/SKU/抑制/备注/UUID；不存凭据，校验长度与字段。存储失败/损坏时发送前拒绝 |
| 双标签或换选择会产生另一请求 | 复用WO恢复模式，以Web Locks串行同账号操作；有未确认记录时不静默覆盖或分配新键 |
| 无法区分未响应与未建单 | 独立GET只读核对，和执行共用原请求锁，等待正在提交的原单；不自动POST或审批 |
| 成功后工作区读取失败被说成建单失败 | 执行POST仅回规范化请求键与原单凭据；工作区后续读取独立处理，成功不再依赖无关读操作 |
| 只显示短暂成功提示 | 持久核对卡展示原周期/选择及原单当前状态；打开准确BH；再次核对服务器回执后才清除此键，准备下一笔 |
| 尚未建单但选错条件无法修正 | 先只读核对，明确确认后沿用原键修正；若原单已提交，找回原单而非新增；异参旧回执仍409 |
| 已关闭周期查不到开单历史 | 关闭后仍可读取冻结行及原单；隐藏新开单入口，服务端继续拒绝新请求；不重开周期 |
| 历史链接未裁剪BH范围 | 单号/链接/制单人按既有本人或共享渠道范围裁剪；共享计划的“已开”事实仍保留，避免把不可读误报成未开 |
| 执行读取失败伪装成空表 | 清除旧数据、显示“尚未获取”与重试；失败不显示“无单”，换周期后旧响应不能覆盖当前表 |
| 开单依据默认保留三位小数 | 浏览器发现12.3456显示成12.346；改用已有`formatQty`，去尾零而不舍入冻结数量 |
| 非法周期筛选退化为全工作区 | 非法/重复周期或请求键、两个查询模式同时出现均400，不静默取消筛选 |

原请求回执查询仍在拥有事务内回查启用身份、已提供会话版本、PMC/admin、原发起人和原BH可读范围；跨人403，不泄露原单号。旧回执缺原意或UUID大小写歧义保持拒绝，不回填或改写历史事实。
