# 发退料与委外收货明确选仓验收 · 2026-09-13

## 范围与结论

同一家加工厂可有多个委外仓。旧公共查询`limit(1)`使FL、TL建单及SH入库各自猜仓；单个仓的库存可能因此增减错误。当前候选保留原账本、单据和审批，不增加分配系统或数据库迁移。

| 路径 | 明确依据 | 并发/失败保护 |
|---|---|---|
| FL发料 | 建单保存`toWarehouseId`；仅JG加工厂启用的实时委外仓 | 创建及审批按仓ID排序加锁后重查；拒绝不留下单据/审批/审计半笔 |
| TL退料 | 建单保存`fromWarehouseId`；同样的身份限制 | 保留原JG累计TL≤FL、冻结结算与批次规则，不冒充实物预留 |
| SH委外入库 | 仓管确认入库时选择`outsourceWarehouseId`，原审计记录ID/编码/名称；库存流水存实际扣料仓 | SH→JG/PO→有序仓锁；当前仓状态重查；重复确认409；审计失败库存/状态一起回滚 |
| 历史追溯 | 详情读取本SH原过账负向流水的仓库，不按当前第一仓推断 | 无扣料流水明确标注“没有物料扣减流水”，不伪造仓或0库存 |
| 选项/UI | 服务端按加工厂/类型/记账/启用先裁剪，再分页/搜索/已选补取；JG切换撤下旧选择 | 坏ID、越界ID、重复参数400；FL/TL长表单复用共享视口滚动约束，创建按钮不应被挤出手机屏幕 |

兼容：旧调用可省略仓库，仅当该加工厂恰有一个合格仓时解析成功；多仓409且有用户选仓入口。采购收货不允许携带委外扣料参数。无新迁移、依赖、独立台账或技能。

## 保留问题

明确仓库不等于跨工单库存分配、可领用量、预留或到料资格。原允许委外负库存策略不因这次选择器改动而改变；毛需求与TL累计依旧是现行政策，不从选仓推导精准剩余物料。已停用的历史FL/TL草稿不会自动换仓；须核对后恢复正确仓或另行走纠错流程，不能静默挪动旧依据。
