# 公网隧道进程归属复核

## 问题与交付范围

基线bb72b66的安装器和卸载器按`cloudflared tunnel --no-autoupdate`批量终止进程；守护按片段取第一个PID，再结合本目录旧日志接管。另一项目的隧道可以被误停或错误配对。守护TERM也会杀掉子隧道，与升级保持地址的意图冲突。

本轮只调整公网进程生命周期，不改交易、身份认领、业务数据、外部授权或公网方案。不执行实际安装/卸载；受控切换与真实公网UAT另行验收。

## 实现

- `tunnel-process-owner.py`把直接子进程的UID、PID、启动时间、完整命令写入本目录600权限原子记录。命令必须含固定HTTP/2、准确本机端口及本目录`--pidfile`标记；cloudflared自身pidfile不作为唯一归属证据。
- 状态和停止操作读取当前进程身份；不按命令片段接管，不批量发信号。陈旧PID即不属于本项目：如果已复用成其他进程，不终止它，也不因此永远阻塞新隧道。发现同入口未登记隧道则拒绝自动操作，防止错误接管或并起两条。
- 固定目录内永久锁文件由守护持有，独立cloudflared显式关闭锁FD；升级旧守护保留隧道，新守护可以验证后接管同PID、同地址。卸载先确认守护退出，再取锁并停止已确认隧道。
- 停止只发TERM；5秒内未退出会报错，不强杀、不继续启动替代隧道。损坏、权限不安全、命令错误的记录拒绝使用，且错误日志不输出完整命令/记录/异常载荷。
- 安装不再清空旧地址；成功必须有已登记活进程、公网健康和同入口登录回跳，而非只看URL文件存在。
- 运维语法门新增卸载脚本和Python编译校验；不生成pyc，不新增npm依赖。

## 证据与反例

使用隔离状态目录、合成端口39871/39872及无网络原生C进程模拟cloudflared参数。macOS和Linux（Python3.13+procps）探针验证登记/状态、陈旧身份拒绝、同入口未登记拒绝及仅停止本项目进程。

实际守护代码的隔离测试仅替换外部Docker/HTTP/应用操作和QA路径：旧守护退出后子隧道存活，新守护接管同一PID及地址，竞争守护返回75。测试不连接Cloudflare、不调用launchctl、不改业务应用、不发通知。

故意删除未知同入口进程的拒绝分支，针对性测试真实变红；恢复后通过。其他用例覆盖被篡改PID/启动时间/命令/UID、损坏或公开可读记录、非启动者登记、父进程崩溃后接管、锁释放、其他端口继续存活。完整候选验收须提交后执行，旧READY不继承。

首候选cdfc614构建成功后，额外检查发现`ps lstart`受调用方TZ影响，可能把同一进程误判为身份变化。已用UTC/上海/洛杉矶的失败测试重现，固定身份采集为UTC+C locale；修正后的新提交需重新构建和完整验收，不沿用cdfc614产物。

## 运维边界与旧版切换

1. 宿主需要Python3、标准ps（macOS或Linux procps）和cloudflared；测试机另需C编译器构建无网络夹具，不是应用容器运行依赖。
2. 现有旧守护没有归属记录，不能伪造记录或仅凭PID自动迁入。先由操作人确认该隧道确属本项目及允许短暂换址，再在受控窗口停旧实例、安装新守护并验证真实HTTP/HTTPS登录。此次未执行此切换。
3. 这是同主机/同用户、协作式进程管理。`ps`身份核对与`kill`在macOS不是一个原子内核句柄；不声称能抵御同用户恶意篡改、极端PID重用竞争、原始命令绕过或跨主机竞争。状态目录应保持700、记录600，不手工删持锁文件。
4. 快速隧道在cloudflared真正重启后仍会换地址；此修复不提供永久域名，不证明公网链路性能或外部集成已完成。

参数依据：[Cloudflare官方运行参数](https://developers.cloudflare.com/tunnel/advanced/run-parameters/)（pidfile在首次成功连接后写入，因此不把它当启动登记或权限凭证）。
