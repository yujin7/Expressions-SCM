## 本轮改进

| 之前的风险/负担 | 本轮行为 |
|---|---|
| 待办页启动就读取全部人员，失败被吞成空数组 | 去掉全量目录hook；打开选择器才按页读取，失败、读取中和无匹配分别显示 |
| 大量人员挤进级联菜单 | 单一“改派给…”入口打开最多480px且不超过视口的确认侧栏 |
| 同名账号只显示姓名 | 始终显示“#ID 姓名 · 角色”，真正选择/提交使用数字ID，不以姓名认领 |
| 人员不在前50条或当前筛选内 | 已选值按精确ID补取；搜索支持姓名、中文/英文角色和#ID；每请求最多50人，可明确加载更多 |
| 选中候选便立即写入 | 先选人、展示完整编号与角色，再明确确认；选择后收起候选，防止继续按键时误选默认行 |
| 页面刷新后任务已被他人修改 | 仍提交打开时所见版本；原版本冲突/原请求核对沿用已有链，不偷偷更新版本掩盖冲突 |
| 改派写入后丢回复 | 侧栏显示未确认并禁止新改派，直接进入原操作恢复；核对/确认清理不再PATCH |

共享`TodoAssigneeSelect`复用已有`RemoteSelect`的取消旧读取、分页、失败重试及精确标签补取；新建和改派两入口同步替换，未保留旧`assigneeOptions`或全量目录兼容路径。API只返回id/name/roles及total，当前启用过滤、当前责任人排除、严格参数校验与private/no-store。没有新增派工角色政策：候选仍是原有规则下的启用账号，保存端仍负责当前权限/人员资格核对。
