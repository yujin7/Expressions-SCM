## 验收分组（不替代101条，也不预先判完成）

| 需求组 | 必须取得的端到端证据 |
|---|---|
| 四屏/数据来源 | 每屏当前角色可读；来源、截止、覆盖、失败原因可见；卡片钻取同一粒度/期间 |
| 库存数量/金额日月序列 | 日出入库与余额可核对、月末/环比一致；估值成本覆盖单列；缺历史不补零 |
| 销售金额及库存占比 | 财务受控修订留痕；默认隐藏与无权限不可读分开；45–47%目标口径与实际分母明确 |
| 库存与销量预警 | 分级、日/7/15/30日销量、30+15+5来源、连续3天涨幅规则与样本/覆盖门正确，红色不掩盖未知 |
| 仓库与调拨 | 仓/地区明细及周转可追溯；线路类型、费用、批次均价、异常、调拨或采购到草稿再执行 |
| 备货权责与过渡 | 单一规则主体、常规/重点SKU分工；运营提报核对、试点和三个月过渡有真实负责人及证据，不假设自动移交 |
| 周期/前置备料/紧急需求 | 成品加工/在途、部件采购周期可补录且被消费；前置包材和OEM需协议/库存归属；10–20天是目标不是事实 |
| 采购订单与降本 | 按批准起点看数量/金额/交付；基线、币税单位、原始承诺可追溯；独立采购二期范围仍须确认 |
| 供应商账期 | 合作满2年、两年排名上升按池可核查；45–60天谈判与达成，采购额代理不冒充应付余额 |
| 待办/部门目标/飞书 | 分派→看到→处置→进度→结果；本人/部门权限；送达不等于读过；绩效口径未定不自动评分 |
| 数据质量 | RPA/人工/外部分类、控制总量、90–95%目标；连续合格周证据与月核对转换；RPA不天然等于100%准确 |
| 多源BI/平台接入 | 品牌/渠道/仓的粒度与身份一致；天猫/拼多多、聚水潭、海外仓逐源授权/映射/对账；“水盘”指代待核实 |
| 体验与验收方式 | 线框与业务确认、桌面/手机/键盘、真实长数据、失败恢复与下一步；不强迫补全全部历史再启用当期流程 |
