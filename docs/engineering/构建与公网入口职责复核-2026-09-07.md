# CI构建与公网入口职责复核

日期：2026-09-07；基线bce7676；本候选未部署。

## 发现与选择

1. CI直接docker build不传版本，构建身份为unknown。
2. 公网安装器直接build app，绕过发布脚本的旧镜像保护、备份和迁移门。
3. 守护用可变镜像标签重建app，同机后来一次build可能使地址同步意外换成另一个版本。

选择：CI只构建已核对源码；访问入口只配置已发布应用。不在安装器再复制一套发布流程。
保留HTTP/2、健康+登录回跳探针和地址通知机制，不声称Quick Tunnel成为永久域名。

## 实现

- `scripts/build-ci-container.sh`取实际Git根目录、干净HEAD并构建前后复核，传入源码版本和HTTPS构建开关；CI调用它。
- `scripts/tunnel-app-guard.sh`由安装器及守护共用，精确查Compose app；实际容器内健康检查须满足源码身份、DB/迁移和正数HSTS。
- 安装器在复制配置/安装守护前执行上述门，缺少条件时不构建或部署。守护及helper必须同提交一起安装。
- 地址更新用临时Compose覆盖固定运行镜像完整摘要，`--no-build --no-deps --pull never`；不启动数据库，不执行迁移。
- 容器变化/多目标/镜像未知/健康失败拒绝；成功更新后再次确认相同镜像及版本，再公布链接。
- shell语法进入`check:ops`；新增实际Git+命令替身行为测试、真实Node健康契约测试、镜像固定/失败传播/起止身份反例。

## 证据边界

首轮7项入口契约失败，证实旧入口直接构建及新受控构建缺失。后续隧道夹具出现两项错误（对象箭头函数语法、命令输出被生产脚本正常抑制），已修夹具并重新执行；不是生产功能缺陷。
定向6文件90项、后续5文件67项、三组类型及全量lint已通过。旧agility-loop护栏对CI内联命令的断言曾失败，已保留容器构建要求并改为检查被调用脚本与版本参数，不再要求不安全的旧命令文本。
另发现原`bash -n a b c`只检查第一个文件，后两个只是参数；改为逐脚本检查8项，最后一项失败会阻断语义门，合成命令替身测试覆盖。
正式候选仍需精确提交完整门及隔离真实Compose运行；不继承bce7676的READY。

没有执行实际公网安装器/守护，没有部署3100，没有向飞书发消息或连接外部业务接口。原工作区保留。
镜像固定不是密码学来源签名；容器起止复核不是发布锁。正式发布与访问配置操作仍必须串行。
该改变防止隐式源码发布，不证明所有运行环境配置与已部署配置逐字段相同；环境变更仍由发布负责人核对。

## 官方语义核对

- [Docker Compose up](https://docs.docker.com/reference/cli/docker/compose/up/)：不构建、不启动依赖、禁止拉取是三个不同选项。
- [GitHub工作流事件](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows?apiVersion=2022-11-28)：PR工作流的提交身份可能是合并提交，必须以实际checkout为准。
