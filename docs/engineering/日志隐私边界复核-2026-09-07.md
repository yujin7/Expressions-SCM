# 日志隐私边界复核

日期：2026-09-07。独立候选基于 `043a479`，未发布；不改真实业务数据、授权、库存或 D69–D71。

## 证实的问题与修复

1. 用友任务先向 console 写原始异常，再净化 job_runs 摘要。现外部任务失败只输出应用生成的安全摘要和错误编号；
   任意上游报文（包括无标签凭据）不直接复述。失败仍为失败，用友五字段摘要协议不变。
2. logger 与 error_logs 原样保存错误、堆栈、路径。现共用凭据/URL/SQL诊断保护；嵌套对象限深、限量，
   不调用自定义 getter/toJSON，不原地修改对象。Error cause 保留安全代码，不复制 params/detail 等原始属性。
3. PostgreSQL 可以把原始输入直接写在 cause.message，不含 SQL/params 标签。真实PG反例证明第一版关键词过滤不足，
   已加入 SQLSTATE 识别，保留代码和可用堆栈位置，移除原始 SQL/输入值。普通非敏感诊断文字仍保留。
4. pg-boss、CLI、export-worker 的已发现 console.error 出口收口。未知导出错误的任务、列表与返回只保留错误码，
   不再向用户输出数据库异常；未知类型/停用账号等明确业务拒绝保留中文说明。
5. 不能为了安全删掉恢复线索：简道云应用生成的成功/失败数量、失败流和刷新键通过 TaskDiagnosticError 明确标记；
   原始 cause 不进入这些摘要。普通 AggregateError 不能冒充可信摘要。直接外部 CLI 与调度共用同一策略。
