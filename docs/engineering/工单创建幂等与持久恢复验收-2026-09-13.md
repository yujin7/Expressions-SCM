## 实施内容

| 原缺口 | 现在的行为与边界 |
|---|---|
| 请求已提交但响应丢失，用户再次建单 | 手工POST强制UUID请求键；当前账号+请求键串行化。同一规范化意图返回原WO，改数量/来源/工厂等则409，不另取号、不重写审计 |
| 只靠页面禁用按钮不能保护刷新/多标签 | 发送前持久保存账号隔离的有限字段草稿；同源同浏览器账号使用Web Locks串行，同步点击/迟到响应/卸载不能另发新键或清掉后续请求 |
| 关闭页面后不知道是否已建 | GET创建结果只回当前账号自己的最小单据凭据；查询不创建。提供核对结果、重试原请求、打开准确WO，以及再次核对后准备新工单 |
| “未找到”被误当作可以直接重建 | 不自动换键；允许显式修改原请求但沿用原键，服务端若已成功则拒绝不同意图。超时/格式异常/存储失败明确提示，不自动重发 |
| 回执与WO可能分别成功 | 新表`wo_create_requests`与WO及创建审计同事务；账号+键、WO各自唯一，指纹格式约束，数据库禁止UPDATE/DELETE/TRUNCATE |
| 已保存回执被当作永久授权 | 创建重放、结果读取仍回查当前启用/角色/会话；撤权拒绝。只返回请求键、ID、单号、状态，不暴露金额或指纹 |
| 手机长表单把错误藏在上方 | 弹窗正文有独立高度上限与滚动；错误或结果出现时正文回顶部，标题及底部动作保留可见 |

指纹固定字段顺序并使用数量/费用的规范十进制串；不把后来变动的BOM/供应商名称混入请求身份。内部自动链调用保留原契约，**不能由手工POST幂等推断其他生成写端全部幂等**。取号、审批职责分离、库存唯一写入及金额脱敏权威不变。
