## 2. 七项技能逐项判断

以下是本轮改进优先级，不是将互补技能评分后相互淘汰。

| 顺序 | 技能 | 保留的价值 | 本轮处理 / 后续验收 |
|---|---|---|---|
| 1 | design-supply-chain-flows | 从角色、事实、决策到动作的完整闭环 | 已强化发现描述，增加按需体验参考：导航/搜索竞态/紧凑布局/指标口径/键盘/真实浏览器证据 |
| 2 | measure-first | 防止没有证据的缓存、队列、架构改造 | 已区分开发反馈与发布证明，要求比较替代工具的覆盖和维护成本；尚未声称工程耗时降低 |
| 3 | supply-chain | 跨域取舍与顺序 | 已加入用户影响驱动的任务—证据图，防止零散清理挤占主目标；不扩大授权 |
| 4 | release-sweep | 精确版本、完整检查、运行边界 | 已澄清文档/技能验证不是应用 READY；禁止混有代码或测试改动时假装只改文档 |
| 5 | integrate-supply-chain-data | 来源、身份、覆盖、对账与拒绝解释 | 保留；后续 BI 改动调用其事实约束，不再增加独立“数据真相技能” |
| 6 | write-path | 权限、事务、过账、精度、审计 | 保留；体验优化一旦涉及认领/审批/写入就启用，不能因想快而绕过 |
| 7 | parallel-sessions | 保护其他会话、工作区和运行进程 | 保留为必要时的安全约束；不因名称而自动启动多个代理 |

技能自动发现不是承诺每次全部激活。官方说明支持描述匹配、按需读取、仓库目录向上扫描及符号链接；
当前会话仍应核实实际可发现项。参见 [OpenAI 技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 3. 工具方案比较

| 方案 | 能补什么 | 成本/风险 | 当前选择 |
|---|---|---|---|
| 现有共享组件 + 定向行为测试 + 隔离浏览器验证 | 快速复现状态错误，并检验真实布局/键盘/请求 | 需维护少量高价值场景；mock 不能替代浏览器 | 首选，立即用于搜索/帮助/表格三条路径 |
| 增加 Vitest 3 Browser Mode 的小范围试点 | 用真实浏览器测组件事件/焦点，减少自制 hooks harness 的局限 | 增加浏览器提供器、安装和 CI 环境维护；收益尚未实测 | 仅在现有浏览器回归不够稳定时做一条路径 A/B 试点 |
| 全站一次性换测试框架 | 可能统一测试写法 | 大量迁移，早期收益不直接落在用户体验上 | 不选；先迁最容易漏报的交互场景 |
| 换 UI 库 / 全站重写 | 可重设外观基础 | 权限、表单、列表、兼容性全部回归；根因是状态与布局契约，换库不保证解决 | 不选；保留 AntD5，修共享组件和实际消费者 |
| 引入独立 BI 平台或第二套指标层 | 在大量业务人员自助建模时可能有用 | 新身份权限、指标同步、部署与对账成本；当前没有证明是阻塞点 | 暂不引入；复用 metrics、报告和钻取 |
| 扩成大量技能/插件/自动代理 | 可覆盖更多外部能力 | 发现噪声、重复规则、工具权限与维护面增加 | 本轮不安装、不启动；有明确缺口和用户范围再选 |

Vitest 的真实浏览器模式确实存在，但本仓是 3.x，应读 [Vitest 3 文档](https://v3.vitest.dev/guide/browser/)，
不能直接套用最新主版本配置。本轮没有升级项目依赖、安装插件或启动外部自动化。

当前优先工具链：`rg`/Git/文件检查定位 → 定向 Vitest/类型/lint反馈 → 隔离浏览器验证 →
一致候选完整发布门。API/CLI适合事实读写契约，浏览器适合用户交互；不拿其一代替另一种证据。

4. `authoritative-sources.md` 的研究日期仍为 2026-07-25：它已明确要求重新核验，不能将整个索引
   一键标成今天已更新。本轮只研究技能、UI与测试工具，不冒充已复核全部国际法规。
5. 体验参考留在 workflow 技能的按需文件，不把完整 UI 手册加载进每次库存/金额修复。
6. 现有 hooks 行为夹具可复用理念，但提取共享夹具应先证明重复维护成本；不在本轮顺手造测试框架。

## 5. 后续产品改进顺序与通过标准

| 批次 | 需要得到的真实结果 | 验收证据 |
|---|---|---|
| A 搜索/导航 | 找得到全部允许访问的注册页面，点得动；同名记录不串；旧查询不污染新查询；失败可见 | 本次 9 项反例转绿，补权限/query深链测试，真实浏览器键盘/关闭/返回验证 |
| B 帮助/紧凑布局 | 解释可键盘/触屏打开，长中文不溢出，表格工具与指标不挤/不浪费空间 | 公共组件 + 多个消费者，桌面/窄屏/缩放截图及焦点行为；保留单位、风险提示 |
| C 任务式信息组织 | 按“发现问题→评估→执行→复核”找入口，合并页签不丢书签 | 角色任务图、入口步数前后比较，菜单/搜索/API权限一致，旧深链仍可达 |
| D BI 到行动 | 图表回答一个明确问题，筛选/期间/单位/覆盖可追踪，点击到对应处置 | 汇总与明细对账，同截止日，未知不当0，钻取不越权、不换口径 |
| E 真实采用与闭环 | 真实负责人完成真实待办，反馈可用于学习而非只刷新 | 用户确认的职责和真实操作记录；工程合成数据不能代签 |

已证实 A 的缺陷：数据响应清空页面跳转 Map、同名实体键碰撞、关闭后迟到数据重新出现、
两个搜索入口换词仍暴露旧候选、快捷面板乱序覆盖、页头请求失败被吞。
静态发现但未浏览器核实：CaliberNote 的无 href 锚点触发器、DecisionMetric 的仅 hover 提示、
query 页签的侧栏选中态。不要把这些不同证据级别全部标成“已修复”。

交互准则参考 [W3C Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)、
[Carbon 表格使用](https://carbondesignsystem.com/components/data-table/usage/)、
[AntD Tooltip](https://ant.design/components/tooltip/)；只借鉴适合的模式，不引入新 UI 体系。

## 6. 怎样证明技能真的更好

元数据和链接通过只是包装合格。下面的任务用于后续真实使用评估，不是已完成的独立盲测。
比较旧/新指引时保留同一代码基线、输入和副作用范围，记录完成率、漏报、返工、时间和新增依赖。

| 输入任务 | 合格表现 | 不合格表现 |
|---|---|---|
| “截图里工具栏太挤，全部修好” | 先核对截图/运行版本，再复现共同组件和多个页面 | 看到旧图就全局改 padding |
| “搜索后点击页面没反应” | 数据响应前后都测试页面与实体；验证乱序/清空/重复名称 | 只测关键词过滤函数 |
| “这个 KPI 不好看” | 先核对单位/分母/未知，再调整网格和帮助 | 把未知变成绿色0，或只缩小字体 |
| “迭代慢，换框架” | 分阶段计时，比较最小替代方案和维护成本 | 无基线引入缓存/新平台 |
| “改供应商银行账号” | 进入写路径约束并核对审计/权限/清空语义 | 只改表单样式 |
| “全部做完了吗” | 锚定候选/部署/业务验收，明确未修和缺证据 | 用总测试数或健康接口替代全流程 |

没有独立代理盲测或使用率提升数据时，不能宣称新技能显著优于旧版。本轮改善有证据支持的
覆盖缺口，后续必须由上述真实任务和浏览器结果继续校验。
