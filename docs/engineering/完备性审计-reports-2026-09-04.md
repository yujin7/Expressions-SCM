# Completeness audit — `/report/*` (30) + cockpit/workbench/goals/todo/alerts/notifications/inbox/review

Repo root: `/Users/yj/Downloads/供应链系统 PRD/supply-chain`. All line refs are from the current working tree.

## Headline

The report layer is in far better shape than typical — most pages carry real read models, calibre notes, five-state empty handling, and role-aware money stripping. The gaps cluster in five places, not thirty:

1. **One genuinely broken call site**: `src/components/CommandPalette.tsx:47` fetches `/api/inbox/search`, which no longer exists (`src/app/api/inbox/` contains only `route.ts`, `approval-brief/`, `batch-approve/`; the search route moved to `src/app/api/search/route.ts`). The failure is swallowed by `catch { /* ignore */ }` on line 58, so ⌘K entity search silently returns nothing on every page in this scope.
2. **The async export path is a dead end.** `EXPORT_KINDS` in `src/server/modules/report/export.ts` registers exactly 5 kinds (`balance` :131, `盘点明细` :181, `ledger` :222, `库存单据` :258, `结算汇总表` :295) — **zero** `/report/*` pages. Nothing in the UI POSTs to `/api/export/jobs` (only `exports-client.tsx:52` GETs and `:117` downloads). Three pages print "请缩小筛选范围，或改用「导出任务」" into a CSV footer row (`inventory-analytics-client.tsx:313`, `detectors-client.tsx:111`, `risk-client.tsx:133`) pointing at a page that cannot create the job they need.
3. **Money role-gating is inconsistent in exactly one place.** `/report/price-compare` shows supplier purchase base prices to every logged-in user: `src/app/api/report/price-compare/route.ts:12` is `guardRead()` only, `src/server/modules/report/price-compare.ts:8-9` explicitly documents that `maskSensitive` is *not* wired, and `src/lib/route-access.ts:108` gives the entry no `roles`. Compare `/master/feeref` (route-access.ts:160, `roles: ["purchasing","pmc","finance"]`) and `/report/margin` (`src/app/api/report/margin/route.ts:21` `requireAnyRole(user, ...PRICE_VISIBLE_ROLES)`).
4. **Two menu/permission mismatches** in `route-access.ts` (details in §a).
5. **Four "0 instead of no data" pages** whose KPI strips render confident zeros when the fetch fails (they also lack `LoadErrorAlert`, so the only error signal is a toast that disappears).

## (c) Top 8 synergy / merge opportunities

**1. Four "home" pages compete for the first screen.**
`/workbench` (control tower + next actions + role focus), `/cockpit` (four screens, exception-first), `/report/dashboard` (BI overview), `/report/digest` (morning brief). The registry already tried to fix the naming (`route-access.ts:71-73` carries an audit comment about "三个驾驶舱并列不可分辨") but the page titles still collide: `report/dashboard/page.tsx:6` = 「经营驾驶舱」, menu = 「经营分析总览」, `/cockpit` = 「驾驶舱四屏」.
**Recommend:** keep `/workbench` (personal, actionable) and `/cockpit` (org, exception-first). Retire `/report/digest` into a `?view=digest` mode of `/workbench` — it renders the same `workbench/focus.ts` exceptions. Rename `/report/dashboard`'s H1 and metadata to match its menu label.

**2. Three lead-time numbers, three calibres, three homes.**
- `purchase-order-metrics.ts` (`:583`): 审批 → 首批生效 SH, shown on `/report/purchase-orders` and cockpit S2.
- `leadtime-learning.ts` (`:11-27`): `po_docs.created_at` → earliest effective `sh_docs.created_at`, shown on `/report/leadtime-learning` (planning group).
- `supplier-lead-history.ts` (`:24-30`): 简道云 `signedAt`/`approvedAt` → `receivedAt`, shown as a tab **inside** `/report/supplier-scorecard`.
The module headers deliberately forbid merging the *numbers* — correct. But the *pages* are scattered across three menu groups with no cross-links.
**Recommend:** move `/report/leadtime-learning` in as a fourth `supplier-scorecard` tab beside 历史交期观察, so the three calibres sit side by side with their own headers. Keep a planning-group alias to `?tab=leadtime`.

**3. `DecisionReadinessPanel` is rendered twice.**
`data-health-client.tsx:465` (「决策能力解锁」) and `decision-studio-client.tsx:1576` (「能力解锁」) — identical component, two deep links (`/report/data-health?tab=readiness` and `/report/decision-studio?tab=readiness`), and `data-product-work-queue.ts` + `DecisionReadinessPanel.tsx` + `jobs/data-product-gate-watchdog.ts` all deep-link only the decision-studio one.
**Recommend:** keep decision-studio's; retire the data-health tab to a link.

**4. Channel observation is rendered twice from one read model.**
`report/channel-observation.ts` feeds both `/cockpit?tab=channels` (via `cockpit-trends.ts` → `screen-channels.tsx`) and `/report/decision-studio?tab=external` (`channel-observation-card.tsx:29`). Same source, so no drift — but two maintained UIs.
**Recommend:** keep the cockpit tab as a summary that links to the decision-studio tab for the full matrix.

**5. Two 库存总量 pipelines behind two 驾驶舱.**
`/report/dashboard` computes inventory inline from `core/stock-view` (`dashboard.ts:24,340`); `/cockpit` reads the cached `inventory-position/vN` read model (`cockpit.ts:10,211`). Both show "全网在库" on pages a director will open side by side.
**Recommend:** make dashboard consume `loadInventoryPosition` too, or stamp both with the same `source`/`asOf` chip so a difference is visibly a timing difference and not a bug.

**6. Inventory analysis is spread over five surfaces.**
`/report/inventory-analytics` (散点/账龄/周转), `/report/segmentation` (ABC/XYZ/四档), `/inventory/warehouses` (各仓周转), `/inventory/position` (日级/月级走向), cockpit S3 (turnover windows + expiry buckets).
**Recommend:** keep all five (they answer different questions) but add reciprocal links — currently `segmentation` is linked *from* five services but links *to* nothing, and `inventory-analytics` has exactly one inbound link (`data-product-work-queue.ts`).

**7. Two "在途" concepts, no cross-reference.**
`/report/transit` = legacy `transit_refs` external ledger (`transit-client.tsx:306` explicitly "不入实时账本"); `/report/inbound-calendar` + `material-demand`'s 系统 PO 在途 = `core/supply.ts` open supply lines. `material-demand-client.tsx:130-169` already shows both as "旧台账旁证" columns — the right pattern.
**Recommend:** add the same side-by-side framing on `/report/inbound-calendar` (a "另有 N 条存量单在途，见在途参考" strip) so nobody reads the calendar as the whole picture.

**8. `/report/npd` vs `/npd`.**
`/report/npd` (`npd-client.tsx`, 69 lines) is a read-only dump of `transit_refs(kind=npd_node|npd_role)` with hardcoded counts in the tab labels; `/npd` is the live project tracker. They sit in the same menu group (`route-access.ts:141-142`) with near-identical labels.
**Recommend:** fold `/report/npd` in as a 「节点模板」 tab of `/npd` and retire the route.
