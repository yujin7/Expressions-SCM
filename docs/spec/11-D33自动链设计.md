# 11 · D33 分批齐套自动触发链——预演优先设计（0724 会议旗舰）

> 原则：**自动=只产草稿；审批永远人工**（R13 精神）。上线路径：预演 → 单品牌灰度 → 全量。

> 本文保留原设计，不代表全部现行实现或上线状态。2026-09-13的BH明细生成规则以下表及[验收](../engineering/备货明细生成与持久恢复验收-2026-09-13.md)为支撑；业务当前意图只看[CURRENT](CURRENT.md)。第2节余额+FL−TL与现行PO已收到料口径并不等价，真实到厂/占用资格尚待核对，不据本文直接切换算法。

## 1. 触发点与幂等
| 钩子 | 动作 | 幂等键 | 开关 |
|---|---|---|---|
| BH 审批通过 | 按原BH明细自动生成WO草稿；沿用createWo，毛需求不是此时自动审批快照 | `bh_wo_generations`的bhLineId及woId各自唯一；一原明细最多一张自动WO，手工拆单政策不变；旧未分配工单先核对，不猜认领 | auto_wo_on_bh |
| SH 收货过账（材料入委外仓） | 齐套引擎重算该 WO 可产量 → 若新增可产量 ≥ 起订倍数：生成 JG 草稿(batchSeq=N) | jg UNIQUE(woId,batchSeq)；batchSeq=已存在批次数+1；同一齐套水位不重复触发（记录 woId→lastTriggeredQty） | auto_jg_on_ready |

## 2. 齐套引擎（纯函数 + 快照输入）
可产量 = min_over_materials( floor(已到料量_i / 毛单耗_i) )；
已到料量 = 委外仓该料实时余额 + 已发未退（FL−TL 事实）；毛单耗 = wo_lines.grossReq/wo.qty。
新批建议量 = min(可产量 − 已下 JG 批次量合计, WO 余量)，按成品 orderMultiple 向下取整。

## 3. 预演（上线闸）
`releasePreview` 式 dry-run：对全部在途 WO 输出「若开启将生成的 JG 批次清单」（不写库），
供 PMC 核对 1 周；灰度参数（后续按需加 per-brand scope 参数行 scope=brand:<code>）。

## 4. 防雪崩护栏
- 单 WO 自动批次上限 8（超出转人工）；
- BOM 处于 needsReview/近 7 天被改判的产品 → 不自动，只提示；
- 全局开关随时归零（params 60s 生效）；审计每次自动生成记 entity=auto_chain。

## 5. 实施排序
① 齐套引擎纯函数+单测 → ② 预演 API/页 → ③ 钩子接线（默认关） → ④ 灰度 → ⑤ 全量。
