## 2. 采纳的重大缺陷（按主题，初版规格中确实存在）

### 结算与委外账务（初版最重灾区）
1. **R5 公式被反例证伪**：发料 11000/合格 10000/BOM 损耗 5% → 原公式扣款=0，而实际损耗率 9.1%——会议唯一定死的"超 5% 由加工厂承担"被公式自己推翻（BOM 损耗率与 5% 双重容差叠加 + 豁免基数无定义）。→ 重写为逐物料 js_line 计算、单一容差来源。
2. **结算单没有明细行**：不同物料量纲不同（个/kg/米），跨物料轧差在数学上不成立，节约料会冲抵超损料。→ 新增 js_line，逐物料 max(0,·)。
3. **加工费双重应付**：加工费同时挂 PO 行与结算单，无核销规则；且加工费行永远不"收货"，在途视图被永久虚增。→ 加工费不进 PO（与会议流程图一致），JS 为唯一应付载体。
4. **"退回量"无数据来源**：全模型没有委外退料单，该项恒为 0，砍单/剩料场景下扣款被系统性算大。→ 新增 TL。
5. **委外仓永远清不掉**：无损耗核销动作，扣了钱账上还挂"欠料"，同一损耗被追偿两次。→ JS 审批触发核销流水+余额清零校验。
6. **让步接收三不管**：实物入仓账上没有、加工费付不付未定、耗料被当超损扣款。→ 让步入库打标、耗料计入基数、单价审批（D6）。
7. **备品悖论**：加工厂免费送备品反而被扣料钱。→ 备品计入耗料基数、零成本入库、入对冲池。

### 库存与纠错
8. **仅追加账本却没有冲销机制 = 没有纠错能力**：录错一笔收货在 MVP 内数学上不可修正，DoD 必挂。→ 红字冲销单入 MVP，取消反审批。
9. **快照仓数量无处安放**（"不走流水"却又要在 stock_balance 里豁免约束）。→ 独立 stock_snapshot 表；且快照仓整体推迟到 1.1（对齐纪要"暂不优先全仓库拉通"）。
10. **委外仓负余额会被约束拒绝**：发料滞后于收货（垫料）时成品入不了库。→ 委外仓允许负余额=垫料信号，对账页标红。
11. **自有仓→快照仓调拨是账务黑洞**（发出即消失）。→ 调拨在途虚拟仓+到仓核销。
12. **采购退货整条流程消失**（PRD P0 原文有）。→ 新增 CT。

### 规则与数据模型
13. **R1 三处边界**：首购无基准、含税/单位不折算造成假异动、基准被未执行的 PC 污染。→ 终版见 00-A5。
14. **净需求缺失**：一键 PO=毛需求，无视在手 8000 再买 10000，直接恶化 PRD 自己的呆滞 KPI。→ R11。
15. **BOM"快照"实为引用**：改 BOM 追溯改变上月结算扣款；生效版本唯一性无约束。→ wo_line 审批时复制快照+部分唯一索引+行冻结。
16. **每日流水号非 PG 原生能力**、doc_no 无唯一约束。→ doc_counter 行锁+UNIQUE。
17. **实体清单自相矛盾**：审批配置/系统参数/品类损耗率/对账差异/批次主档/附件等被引用却不在清单。→ 28→39 实体。
18. **脱敏"API 层收口"在 App Router 中不存在单一收口**；且矩阵禁止 PMC 看它必须录入的加工费单价。→ dto.ts 唯一收口+lint；PMC 加●；加工费/结算/扣款字段显式入 R9。
19. **过账幂等与乐观锁互相拆台**、余额热点行死锁、批次 NULL 重复行。→ UNIQUE 过账约束+幂等优先+排序更新+NULLS NOT DISTINCT。
20. **附件无存储与备份设计**——检验照片是扣款争议的证据链，灾备后全丢。→ 附件卷+file_meta+入备份。

### 需求还原（对照原文）
21. **PO 电子章/固定合同条款/盖章付款全流程**（会议明确决议）整体遗漏。→ 1.x 打印模板+固定条款，P1 电子签。
22. **供应商确认**（PRD 流程 1）在状态机中缺失。→ PO/JG 确认门。
23. **会议 BI 要求**（公司/部门/项目、同比环比、三级下钻）被简化为"3 张报表"且模型无维度字段。→ 单据头预置维度字段，P2 范围记录原文。
24. **全仓库出库排名/在途/出库数据**、上限/临期预警、盘点定期/永续、多级价格（客户/渠道）、询价实体、ERP 主数据同步、B2B 销售实体——均补阶段归属或 P1 预留。
25. **快照仓拉进 MVP 与纪要"暂不优先"相悖**。→ 移至 1.1（同时化解了 4 项技术冲突）。

### 交付计划
26. **审批权三处文档互相矛盾**（矩阵给采购零审批权 vs 流程图"采购主管审批"）。→ 单一权威审批配置表+is_approver+制单审批分离。
27. **上线数学不闭合**：14 天对账窗口塞不进 6 周、"并行 2 周"越过上线宣告日、"与会议 1 个月完全一致"为不实表述。→ 诚实重排 W0+W1–W6+W7–W8，撤销"完全一致"，列 D8 待追认。
28. **DoD 不可测量**：差异≤1% 无分母/口径/签字人；"无任何 API 可旁路"全称命题无枚举方法；DoD 只测 4 角色漏掉链路发起者运营；脱敏只测运营漏掉仓管。→ DoD 全部重写为可机械执行的定义。
29. **页面/实体计数错误**、结算汇总表有承诺无页面、导入模板三处口径不一、文档尾部残留 markdown 围栏。→ 已订正（27 页/39 实体/8 模板）。
30. **无环境计划、无期初迁移演练、无回退预案、无 UAT 场景矩阵、前置项无到期日**。→ staging+prod、W5 演练、回退预案、≥5×5 矩阵、W0 到期表+升级机制。

## 4. 修订后仍开放的风险（无法由文档消除）

1. **平台改向未追认（D8）**：纪要倾向简道云，自研决策需项目会记录在案——这是本规格最大的单点前提。
2. **时间预期差（W8 vs "1 个月"）**：已如实声明，需管理层接受或砍范围（可砍项：CT 采购退货、报表-1、让步/备品简化）。
3. **单人开发假设**：W2/W4/W5 为高风险周，无第二开发者冗余；缓解=W0 spike+特性冻结纪律。
4. **参数决策依赖业务方**（D4/D5/D6/D7）：品类损耗率最迟 W3 D1，逾期直接阻塞结算开发。
5. **聚水潭手动导出的连续性**（14 天窗口含周末）：责任人未定（随 D9）。
