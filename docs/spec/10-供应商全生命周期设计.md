# 10 · 供应商全生命周期设计稿（D38 / 0724 会议）

> 会议判语：现"仅档案登记"的第一阶段方案过于粗糙，需准入→池→绩效→淘汰全节点设计。
> 本稿=设计基线（P1 实现）；现状已建：四态+黑名单硬门+资质预警+S–D 分级列+D26 档案字段+D24 证照附件。

## 1. 状态机（在现有 supplierStatusEnum 上扩展）

```
待准入 pending ──准入评审(采购发起+品控会签)──▶ 合格池 qualified
qualified ──绩效触黄线/主动观察──▶ 暂停 paused ──整改复评──▶ qualified
qualified/paused ──触红线/连续两季 D 级──▶ 黑名单 blacklisted（禁新 PO/WO 硬门·已建）
blacklisted ──满一年且书面申请──▶ pending（重新准入）
qualified/paused ──业务终止(非违规)──▶ 淘汰 retired（P1 增态：禁新单、档案留存、区别于黑名单）
```

## 2. 节点设计

| 节点 | 动作与数据 | 系统落点 |
|---|---|---|
| 准入 | 提交档案（D26 字段）+ 证照（D24 附件）→ 采购初评 → 品控会签 → qualified | P1：准入审批流（复用 approvals，docType=supplier_admission）；现为 admin 直改状态 |
| 合格池 | 分级 S–D（初始人工，季度评分后自动建议）；询价/下单资格=qualified 且未暂停 | level 列已建；下单硬门已建（黑名单）；paused 软提示已建 |
| 绩效 | 季度评分=质量40（QC 记录）/交付40（PO 准交）/价格20（R1 异动）——D7 参数化；红/黄/蓝事件分级：红=blacklisted（已建）、黄=paused 建议、蓝=记录不动作（0724 会议补） | P1 评分引擎；数据源已全留痕 |
| 淘汰 | retired 态：禁新单、存量收尾、档案与历史评分留存 | P1 增枚举值+迁移（与 paused/blacklisted 语义区分表已备） |
