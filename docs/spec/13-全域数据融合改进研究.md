## 二、本轮核心发现与已实施改进（Wave R：R11+ 全口径融合）

**缺陷（危险级）**：补货建议 R11 的在库=系统口径（电商部覆盖），对 474 个覆盖缺口 SKU
会把海外/其他部门仓已有库存判为零而建议重复采购（E054-000：系统 0 vs 全口径 176,216，
日均 1,173——原逻辑将其排为最紧急并给出巨量建议）。

**已实施**（`rules/fusion.ts` 纯函数 + `replenish/service.ts` 融合 + UI）：

1. **全口径参考列**：stock_summary 文件数量 + 在订未出，缺口 SKU 标「缺口」徽标；
2. **存量在途列**：fg_order 未入库余量（旧流程收尾单，登记口径）纳入管道视野；
3. **全管道可销天数**：(max(系统,参考)+PO在途+存量在途+在订未出)÷日均——参考只调高认知绝不调低（参考层不可当账）；
4. **防重复下单抑制**：缺口 SKU 且全管道充足 → 建议抑制并逐行给出原因（抑制≠隐藏，人工核实后仍可手工开单）；
5. **生产周期风险**：可销天数<常规生产周期 → 「低于周期」红标（sku_leadtime staging 同源 releaseFinishedMoq）。

**实测（2026-07-24 真数据）**：128 个系统口径告急 SKU 中 **106 个为覆盖缺口误报（已抑制）**，
真实建议收敛至 22 个；页首标注参考时点 2026-07-21 与抑制计数。纯规则单测 ×12。
