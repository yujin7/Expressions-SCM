# 质量合规、召回与电子标签 · 当前实现契约

> 状态：当前 revision 的可执行契约。它提供记录、提醒、证据固化和人工闸门，不替代质量负责人、
> 责任人或律师的市场判断。

## 1. 业务边界

本域用一条受控证据链连接四类工作：

1. 投诉与不良事件：锚定 SKU / 批次 / 供应商，由人判断严重性与可报告性。
2. 召回：先固化已知批次范围，再建立围堵、通知、有效性检查和数量核对行动。
3. 年度 GMP 自查：按年度与生产场所唯一，登记报告、发现、CAPA 和有效性验证。
4. 市场合规与电子标签：备案/注册/PIF/安全评估按不可变版本发布；电子标签只绑定一个
   已生效的监管证据版本，旧 token 永不静默改写或重定向。

消费者姓名、电话、病历或投诉正文不得进入通用质量表。系统只保存受控外部证据引用；
在受限证据库和访问审计建设完成前，不把本域冒充医疗/隐私资料库。

## 2. 权威事实与状态

| 对象 | 可变部分 | 不可变部分 | 关闭/发布闸 |
|---|---|---|---|
| `quality_cases` | 只允许服务状态机规定的前向变化 | 人工判断、监管提交、自查报告、结案证据与冻结召回范围均由数据库防改写 | 可报告事件已提交；召回/自查/CAPA 行动已解决 |
| `quality_actions` | open → completed → verified / ineffective / waived | 完成与验证证据不能覆盖；不可硬删除 | 完成人与验证人分离；豁免仅管理员且必须有理由 |
| `regulatory_records` | 无原位修改；变化产生新版本 | 全部历史版本、payload 摘要 | 同 `recordKey` 串成 previous/version 链 |
| `electronic_label_versions` | 无原位修改；修订产生新版本 | token、内容、摘要、监管版本绑定 | 仅产品级、SKU/市场/编号一致且类型获该市场允许的 active 证据可发布 |

案件与行动写入、状态变化和审计在同一数据库事务中完成。外部请求用 UUID 幂等键；案件状态
变化另有乐观锁版本，防止两名质量人员覆盖彼此判断。

## 3. 不良事件规则

- `unassessed` 是独立状态，不能被空值或 `false` 吞掉。
- 美国市场被人工判定为 `serious_reportable` 后，系统按接收日后 15 个美国联邦工作日计算
  提交期限，并保守计算 6 年记录留存，同时建立接收日起一年的补充跟进工作；节假日算法不预测
  临时行政停工。该一年监测行动在到期日前不能由服务或直接 SQL 提前完成。
- 非美国市场的可报告事件必须由质量角色明确提供政策名、期限和留存日期；软件不猜当地法律。
- 报告完成必须写入监管回执引用，关闭前再次检查。
- 期限状态使用明确的 `asOfDate`，不让测试、历史回放或时区改变结论。

## 4. CAPA 与年度 GMP 自查

- 高/严重案件关闭前必须记录根因，并至少建立纠正、预防或有效性行动。
- 行动责任人提交结果和证据后仍只是 `completed`；另一名质量人员验证后才成为 `verified`。
- `ineffective` 不能满足关闭闸，必须继续整改；`waived` 仅管理员可执行并保留原因。
- 年度自查的生产场所展示名会折叠空白并生成大写规范键，按 `规范场所键 × 年度` 唯一；
  大小写/空白变体不能重复建案，建案后场所身份不可改。报告登记后，发现、纠正、预防与
  有效性行动全部解决方可关闭。
- 自查报告留存期从不可改写的报告日开始保守计算不少于 2 年。

## 5. 召回范围与诚实覆盖

召回必须绑定系统批次。冻结时在一个摘要中固化：

- 当前批次库存余额及仓库；
- 该批次库存流水数量；
- 批次效期/参考库存证据；
- 对应 SKU 的外部库存快照；
- 同 SKU 未绑定批次的系统库存；
- 批次过账闸状态与已知限制；
- 系统当前没有客户/渠道去向事实这一覆盖缺口；
- 人工补充的限制说明。

快照用 canonical JSON 计算 SHA-256；冻结后数据库拒绝改变范围、摘要、SKU 或批次。它表达
“冻结时系统知道什么”，不把缺失客户订单/出库去向伪装为完整召回覆盖。
批次余额与无批次余额都按正余额毛额披露；负余额单列为完整性异常和净额旁证，绝不跨仓抵减
召回潜在暴露量。

启动召回前必须先建立围堵、通知、有效性检查与数量核对四类行动。关闭前四类行动必须各自
通过独立验证；这些召回必备工作流不可用通用豁免绕过。

## 6. 监管证据与公开电子标签

- 备案、注册、设施、产品列名、EU PIF/CPNP、安全评估等采用通用不可变版本模型。
- 每个版本含市场、权威机构、引用号、有效/到期/续期日期、结构化 facts、外部证据引用和摘要。
- “最新修订”与“当前适用版本”分开判断：`submitted` 草稿不取代仍有效的旧版；一旦较新
  `expired` / `superseded` / `rejected` 状态修订到达适用日，它会明确撤销旧 active 版本，
  不得静默回退。
- 续期状态是工作提示，不自动改变监管法律状态。
- 电子标签内容经白名单 schema 解析，公开 API 只返回标签字段、SKU 基本信息、版本、有效日期
  和摘要，不返回内部用户、审计、证据路径或监管 payload。
- 标签只接受当前已配置的市场产品级证据类型（CN 备案/注册、US 产品列名、EU CPNP），并要求
  同一 SKU 与备案/注册编号一致。到达生效日后仍须由当前适用、active 且未到期的修订支撑；
  较新终止修订或证据到期时公开页明确显示阻断状态，不误报为“当前有效”或回退到旧证据。
- 当前电子标签是受控试点能力；上线到具体市场前，质量负责人仍须确认该市场、品类和实物标签
  是否允许电子形式以及必须保留在实物标签上的字段。

## 7. 权限

- 只读：质量、采购、仓库、PMC、运营、管理员。
- 案件和行动证据读取回查数据库中的当前账号/角色；角色已摘除或会话版本失效会立即拒绝，
  不沿用旧 JWT。非质量/非管理员只见协作所需字段，完成证据、结果、验证结论和受限引用置空。
- 新建案件/行动：相应协同角色可建立工作；质量角色负责判断、监管证据和发布。
- 质量状态变化与验证：质量或管理员；行动责任人可提交自己的完成证据。
- 价格敏感字段仍由现有 DTO 统一脱敏；新增 `quality` 角色不获得价格可见权。
- 公开电子标签路径无登录要求，但只暴露明确公共 DTO。

## 8. 验证与上线出口

上线前至少需要：

1. PostgreSQL 真实迁移、append-only/frozen-scope 攻击测试和恢复演练。
2. 质量负责人对市场规则、角色、场所列表、外部受限证据库和通知模板签字。
3. 以真实批次演练召回，人工核对冻结摘要与仓库/外部库存，并记录未知客户去向。
4. 用测试 SKU 扫描历史与当前电子标签 token，确认旧版本仍可追溯且页面无隐私字段。
5. 对 FDA 报告期限、NMPA 自查留存和目标市场标签要求做发布日复核。
