# SKU 编码标准 S1

生效日期：2026-07-30
适用范围：未来新建/替代 SKU；历史 SKU 不改码
系统入口：主数据 → SKU 货品 → 编码标准

## 1. 一句话规则

新建 SKU 时将“编码”留空，系统保存时自动生成：

`S1-来源-类型-六位全局流水-两位校验码`

例如：`S1-EXP-F-000123-K7`

这不是把所有业务信息都塞进一个字符串，而是“双层标识”：

1. `skus.code`：企业内部稳定主码 S1，短、唯一、可读，来源段直接区分品牌；
2. `sku_identifiers`：GTIN、包装层级条码、聚水潭/用友编码、供应商/客户料号和历史码。

来源段是“创建时品牌起源”的人类可读快照，不是品牌关系的唯一权威。运行时品牌归属仍以
`skus.brandId → brands` 主档关系为准；两者不一致时必须进入治理流程，不能从字符串反推并覆盖主档。

## 2. 每段是什么意思

| 段 | 示例 | 含义 |
|---|---|---|
| 方案版本 | `S1` | 第一版 SKU 编码规则；未来规则变化必须升版本 |
| 来源 | `EXP` | 品牌起源短码；共享/中性物料用 `GEN` |
| 类型 | `F` | SKU 类型 |
| 全局流水 | `000123` | 企业唯一顺序号，由系统并发安全取号 |
| 校验码 | `K7` | 发现常见误录，不代表审批或权限 |

类型码：

| 类型码 | 类型 | 中文 |
|---|---|---|
| `F` | finished | 成品 |
| `H` | semi | 半成品 |
| `R` | raw | 原料 |
| `P` | packaging | 包材 |
| `V` | service | 服务 |

## 3. 为什么不把更多信息写进编码

渠道、供应商、工厂、规格、颜色、售价、生命周期、当前品牌归属、BOM 父产品和法规市场均可能
变化。它们已经有主档字段或关系表，重复写进永久编码会导致：

- 同一物料因共用或换供应商出现多个编码；
- 渠道、版本或规格调整时被迫换码；
- 历史订单、库存、BOM 和外部系统对照断裂；
- 人工从编码猜业务含义，与系统事实不一致。

所以 S1 只保留稳定身份所需的最小信息。

## 4. 新旧编码如何共存

1. 现有 `E054-000`、`N02-003-a`、`DEV025-0201-1` 等编码永久保留。
2. 不批量重编号，不修改历史单据、库存、BOM、附件或台账关联。
3. 外部系统码、条码和旧码通过 `sku_identifiers` 与既有别名注册表解析。
4. Excel/staging 导入继续接受真实历史和外部编码。
5. 页面新建时推荐留空自动生成；只有确有其码的历史/外部货品才手工输入。
6. `S1-` 命名空间只允许系统原子取号；人工和外部编码不得占用该前缀。
7. 已创建 SKU 的主码不可修改；替代关系通过新 SKU、旧码别名和生命周期表达。

## 5. 操作示例

### 新成品

- 品牌：EXPRESSIONS（短码 `EXP`）
- 类型：成品
- 编码：留空
- 保存结果示例：`S1-EXP-F-000123-K7`

### 共享包材

- 品牌：留空或按主档治理
- 类型：包材
- 编码：留空
- 保存结果示例：`S1-GEN-P-000124-2M`

### 已有外部编码

- 外部系统真实编码：`E054-000`
- 新 SKU：编码留空，由系统生成 S1；
- 在该 SKU 的“标识”抽屉登记 `external`，作用域填写来源系统（如 `JST`、`JIANDAOYUN`
  或 `YONYOU`）；同一外部值必须绑定明确 scope，不能跨系统猜测等价；
- 常见输入别名会标准化：`聚水潭/JUSHUITAN → JST`、`简道云/JDY → JIANDAOYUN`、
  `用友/YonSuite/YonBIP → YONYOU`；未知系统仍保留人工填写的独立大写 scope；
- 0039 迁移为无归属冲突的历史同义 scope 建立 canonical survivor；若同一外部码已指向
  多个 SKU，只进入 `alias_exceptions` 人工裁决，迁移和新建服务都不会静默抢占；
- 既有历史 SKU 主码仍原样保留，不强制转换。

### 同一 SKU 有单品码和箱码

- 单品 GTIN：登记为 `gtin + each`，可设为该层级主标识；
- 箱 GTIN：登记为 `gtin + case`；
- 还可登记 `inner`、`pallet` 或 `other`；
- 系统验证 GTIN-8/12/13/14 的 GS1 Mod-10 校验位；
- 主标识替换会逐条审计旧主标识降级；停用后可重新启用并显式恢复为主标识；
- 受治理外部码同时贯穿共享 staging 与放行引擎；歧义命中进入人工裁决，不自动猜测；
- 不把箱规或条码拼进 S1。

## 6. 管理纪律

- 不用 `MAX+1` 取号；系统使用 `doc_counters` 原子取号。
- 流水允许跳号。跳号不代表丢数据，通常来自事务回滚或碰撞避让。
- 校验码只防误录，不能替代唯一约束、角色权限、审批、审计和外部对账。
- 来源段代表创建时的稳定起源，不因后续品牌归属调整而改码。
- 品牌主档关系是当前业务归属权威；来源段只帮助识别创建起源，不承载可变归属。
- 发现重复主档时只进入人工裁决，不按名称或编码相似度自动合并。
- 主品牌发生实质变化时不改写旧 S1；按业务事实新建替代 SKU/GTIN 并保留历史关系。
- GTIN、客户货号、供应商料号和外部系统码不得互相冒充；必须登记类型、作用域和包装层级。

## 7. 为什么这是当前最优解

没有跨企业、跨行业都“最好”的 SKU 字符串。对本项目，S1 + 独立标识注册表优于纯流水码和
重语义拼码：

| 目标 | 当前方案 |
|---|---|
| 一眼区分品牌 | `EXP`、`NING`、`DEV` 等来源段直接可见；共享物料用 `GEN` |
| 企业内稳定唯一 | 全局原子流水 + 数据库唯一约束 |
| 减少误录 | CRC-8 两位校验码 |
| 不因渠道/包装/供应商变化换码 | 可变事实不进入 S1 |
| 全球贸易与扫描 | GTIN 独立登记，支持每个包装层级不同 GTIN |
| 聚水潭/用友/交易伙伴互操作 | 外部编码按类型和 scope 独立登记 |
| 历史兼容 | 不批量改码；旧码保留并可被解析 |
| 防止脏数据自动污染 | 重复条码不自动认领，进入人工归属裁决 |

这与 GS1 的“GTIN 表达贸易项目、批次/序列另行组合”原则，以及主流 ERP 将内部 item number、
GTIN、供应商/客户货号分离的做法一致。参考：

- [GS1 GTIN Management Standard](https://www.gs1.org/1/gtinrules/en/)
- [GS1 Global Traceability Standard](https://www.gs1.org/standards/gs1-global-traceability-standard/current-standard)
- [Microsoft Dynamics 365 product identifiers](https://learn.microsoft.com/en-us/dynamics365/supply-chain/pim/product-identifiers)
