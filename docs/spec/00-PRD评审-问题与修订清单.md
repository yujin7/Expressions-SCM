# PRD 评审：问题与修订清单

> 基于《供应链系统PRD v1.0》(2026-07-10) 与《供应链系统推进计划讨论会》纪要 (2026-07-23)
> **v1.1 (2026-07-23)：经 4 视角红队审计修订**（领域逻辑/需求还原/技术模型/交付计划），审计报告见《03-红队审计报告》

---

## A. 关键缺口（不解决无法开工 / 无法验收）

### A1. 关键指标全部为空值
PRD §1.3 与 §9 的 KPI 均为占位符。**M6 验收无法执行。**
- **修订**：基线数据采集自 **W0 启动**（计划任务，非口头承诺），W4 前锁定目标值。
- **责任人**：建议 谭莹莹（会议参与人；**任命待项目会确认**）。

### A2. QC 缺失，但已成为承重墙
采购/委外收货均含"检验"节点，供应商评分依赖品控打分。
- **修订**：MVP 1.0 引入最小 QC——收货检验记录（合格/不合格/**让步接收**三数 + 照片备注）。不合格品处理路径必须闭环：**退厂返工（走委外退料/重交）、让步接收（入库+标记+结算单价审批）、报废（红字核销+审批）**。完整 QC 模块列入 P1。

### A3. 单据状态机完全未定义
- **修订**：统一状态机 + **供应商确认环节**（PRD 流程1 要求，MVP 内部代录）+ **作废级联矩阵** + **短关（short-close）** + **红字冲销纠错机制**（取代反审批）。见《01》§4。

### A4. 术语不统一：委外单据体系混乱
- **修订**：统一四层单据：备货申请单 BH → 委外工单 WO → 采购订单 PO（**仅原料/包材行**）+ 委外加工通知单 JG（**携带加工费单价**）。
- **加工费应付载体唯一化**：加工费不生成 PO 行（与会议流程图一致——WO 审批后仅生成包材采购单与加工通知单），应付以委外结算单 JS 为唯一载体，**杜绝 PO 与 JS 双重应付**。若财务要求加工费预算占位（P1），JS 作为其核销单。
- **采购申请单**：PRD 流程 1 的"采购申请"在委外链中并入 BH；**独立采购**允许直接开 PO（需审批）；独立"采购申请单"实体列 P1。

### A5. 价格异动规则未定义
- **修订**（R1 终版）：
  - 比价一律折算为**基础单位、未税价**（消除 箱/个、含税/未税 假异动）；
  - 基准 = 该供应商该 SKU **最近一次终审通过的 PO 价**；无历史价 → 价格表价；**均无 → 首购免检，终审后自动立基准**；
  - |偏差|>3%（参数）→ 强制价格变更申请单 PC；PC 必填**生效范围（仅未收部分/含已收追溯）**；
  - **基准更新绑定 PO 终审通过**（而非 PC 通过——防止被从未执行的价格污染）。

### A6. 库存账实模型未定义
- **修订**（R4 终版）：
  - 自有仓（成品/原料/包材/委外/调拨在途）：实时流水制，账本仅追加；
  - 快照仓（保税/E/云）：**独立 stock_snapshot 表**按天覆盖导入，**不进 stock_balance**（消除约束冲突）；**MVP 1.0 不启用快照仓，1.1 启用**（对齐会议"暂不优先推进全仓库数据拉通"）；
  - 自有仓→快照仓调拨：借记**调拨在途（虚拟仓）**，到仓确认后核销（防止货物在账上凭空消失）；
  - **委外仓允许负余额**（=加工厂垫料，业务上有真实含义），对账页标红；其余自有仓禁负库存；
  - 在途 = 已审批 PO 未收货数量（**仅实物行**，加工费已不在 PO 内故无虚增）。

### A7. 产品归集规则——SPU/SKU 双层模型（决策提案）
同 v1.0。SPU=报表/库存归集口径，SKU=交易/BOM 口径，改名不断历史。

### A8. 销售数据的系统边界
聚水潭 = 电商销售 SoT。本系统按天导入自有仓发货口径的出库数据；**实时库存回传电商平台、物流单号回传：明确不做**（聚水潭自身承担平台同步职责，PRD P1 该两项据此裁剪，需产品会确认）。B2B 销售订单 P1。销售退货 P1（电商退货在聚水潭闭环）。

## B. 需修订（影响健壮性）

### B1. 委外结算公式（重写——原公式经审计证伪）
原公式三处致命伤：跨物料轧差量纲不成立；BOM 损耗率与 5% 双重容差叠加；"实收合格数量对应发料量"无定义（举例：发料11000/合格10000/BOM损耗5% → 原公式扣款=0，而实际损耗率9.1%>5%，会议唯一定死的规则被公式推翻）。
- **修订**：**逐物料明细行计算**（js_line），单一容差来源（品类允许损耗率，包材=5%；BOM 行损耗率仅用于计划发料，不参与结算），有效完工数=合格+让步+备品，扣款单价=当月加权平均价（与 B2 计价口径一致）。完整公式见《01》R5。
- **配套单据**：委外退料单 TL（"退回量"的数据来源，原公式该项恒为0）；JS 审批触发**委外损耗核销**流水，该 JG 委外仓余额强制清零（否则扣了钱还挂"欠料"，同一损耗被追偿两次）。

### B2. 成本核算：系统职责与财务方法解耦
同 v1.0：数量流水永远准确；计价用月度加权平均；对冲池独立台账，季度冲销。**备品定价规则补充**：按当月加权平均价入池。

### B3. 非功能指标定稿
并发统一 100；账实一致性≥99.9%（盘点差异率）；"95%"限定为迁移数据完整率；decimal 精度；幂等+乐观锁（**幂等键判定优先于版本冲突**，过账表加 UNIQUE(来源单据类型,id,动作) 硬约束防双重过账）。

### B4. 权限矩阵缺维度（修订版见《01》§6）
- 增加：审批权 A、敏感字段●、**客户档案行**；
- **职责分离**：系统级强制"审批人≠制单人"；同角色内以 is_approver 标志区分审批人（不新增角色）；
- **仓库类单据审批权下放仓管审批人**（原矩阵全压管理员，日均30张单必然瘫痪）；
- **PMC 必须有●**（其录入加工费单价、创建结算单，"必须录入自己无权看见的价格"是矛盾）；加工费单价/结算金额/扣款单价**显式纳入 R9 敏感字段清单**；运营对 WO 的读权限做字段级隐藏加工费。

### B5. 编码规则
"PG sequence per day"非 PG 原生能力——落地为 **doc_counter(prefix, biz_date, last_no) 行锁表 + UNIQUE(doc_no) 兜底**。

### B6. 实体清单重构
28 → **39 实体**（补：批次主档、附件、审批配置、系统参数、对账差异、doc_counter、stock_snapshot、TL/CT/红字机制、wo_line/js_line 等；P1 预留 5：销售订单/明细、店铺、询价/报价、客户价格表）。RK/CK/DB 定版为**一张库存单据表 + 子类型 + 三前缀**。见《01》§3。

### B7. 批次与效期
批次主档实体补入；SKU 增加临期预警阈值；**MVP 1.0 关闭态定义**：批次字段隐藏、账本批次列=哨兵值（UNIQUE NULLS NOT DISTINCT）；1.1 开启，同时上线**上限/临期预警**（PRD P0 的三种预警 v1.0 只排了安全库存一种）。

### B8. 委外仓 = 加工厂料账
同 v1.0，并与 §4 过账表对齐：清账动作 = TL 退料 + JS 核销，两文档不再矛盾。

### B9. 采购退货 / 委外退料（原稿整条缺失——审计 4/4 命中）
PRD P0 明确含"采购退货→退款→重新入库"。
- **修订**：MVP 1.0 增加 **采购退货单 CT**（负向收货：库存−、冲减 PO 已收数；应付冲减 P1 随财务集成）与 **委外退料单 TL**（委外仓−/自有仓+，可检验）。销售退货 P1（见 A8）。

### B10. 错账更正机制（原稿为零——仅追加账本没有冲销=没有纠错能力）
- **修订**：MVP 1.0 内置**红字冲销单**：对任意已审批库存单据生成负数流水，引用原单，需审批，全留痕。反审批机制取消。

### B11. 净需求建议（原稿一键生成 PO=毛需求，采购 UAT 第一周必拒）
- **修订**（R11）：PO 建议量 = 毛需求 − 可用库存 − 在途，三个数并排展示由采购确认；按 MOQ/订货倍数向上取整（uom_conv 增字段）。

### B12. 会议 BI 要求落库（同比/环比/公司/部门/项目三级下钻）
- **修订**：单据头预置 公司/部门/项目 维度字段（现在加=一列，P2 再加=全量刷数）；BI 需求原文记入《01》§2 P2 行。全仓库"出库排名/在途/出库数据"列入 1.1 快照模板扩展。
