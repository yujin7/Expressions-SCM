# NPD 新品项目跟踪 — 使用说明

适用对象：销售、产品、PMC、运营
对应菜单：**新品开发 → NPD 项目**
写权限：PMC 或运营（其他角色可查看）

> 本说明对应 2026-07-27 会议行动项「说明书发送与研究：将 NP 项目跟踪相关的系统说明书发送，
> 联合销售同学共同研究」。文中每一步都以系统当前实现为准。

---

## 一、它解决什么问题

新品从提出到上架要经过几十个环节，分散在不同部门。这个模块做三件事：

1. **建项目时自动铺出全部节点并算好每个节点的计划起止日**，不用再各自维护 Excel；
2. **谁在拖、拖了几天，一眼可见**（逾期节点会标红）；
3. **新品要备货时，一键生成首单备货草稿**，直接进入正常的审批流程。

系统**只出草稿、只做提醒，不替人做决定**。所有下单和审批仍由人确认。

---

## 二、节点模板：69 个节点、4 个阶段

建项目时，系统会把模板里的 **69 个节点**整套复制到你的项目里。当前模板分布：

| 阶段 | 节点数 |
|---|---|
| 需求确认阶段 | 9 |
| 需求开发阶段 | 28 |
| 产品投产阶段 | 28 |
| 上线销售阶段 | 4 |

每个节点带**负责部门**和**标准工期（天）**。

**重要**：模板是建项目那一刻**快照**进项目的。之后模板被修改或重导，**不会影响已经在跑的项目** —— 在跑的项目节点不会被人从背后改掉。

---

## 三、建项目

**新品开发 → NPD 项目 → 新建项目**，填四项：

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目名称 | 是 | 至少 2 个字 |
| 启动日期 | 是 | 格式 `YYYY-MM-DD`，全部节点从这天开始往后排 |
| 目标 SKU 编码 | 否 | 如 `E120-000`。**可以先留空**，后面补 |
| 品牌 / 备注 | 否 | |

关于**目标 SKU**：

- 填了就必须是**已建档**的编码，或已认领的别名。填一个系统里不存在的编码会被拒绝，并提示先去主数据建档。
- 填别名也可以，系统会自动**收敛成规范主码**存起来，避免同一个产品在项目里叫一个名、在主数据里叫另一个名。
- 留空不影响推进节点，但**生成首单备货草稿之前必须补上**。

提交后系统会立刻算出全部 69 个节点的计划起止日，并给出项目的**预计完成日**（= 所有节点里最晚的那个计划完成日）。

---

## 四、推进节点

进入项目详情，每个节点可以设成四种状态：

| 状态 | 含义 | 对排期的影响 |
|---|---|---|
| 待办 `pending` | 还没开始 | 按计划工期排 |
| 进行中 `doing` | 正在做 | 按计划工期排 |
| 已完成 `done` | 做完了 | 按**实际完成日**收尾 |
| 已跳过 `skipped` | 本项目不需要这个节点 | **零工期直通**，不推迟后面的节点 |

- 标成「已完成」时系统自动记下完成日期。
- 每个节点可以写备注。
- **逾期**判定：节点未完成（不是 done / skipped）且计划完成日已经早于今天 —— 列表里会标出来。
- 所有状态变更都写审计，能追溯是谁在什么时候改的。

---

## 五、重排计划（关键功能）

实际执行一定会偏离计划。点 **「重排计划」**，系统按下面的规则重新推算全部节点：

- **已跳过**的节点：零工期，不占时间，也不推迟后继；
- **已完成**的节点：按**实际完成日**收尾，不再用理论工期；
- **未完成**的节点：如果它的计划开始日已经**早于今天**，就从今天重新起算 —— 不会把任务排在过去；
- 后面的节点依次顺延。

重排后会告诉你**改动了多少个节点**和**新的预计完成日**。

> 建议用法：每周例会前点一次「重排计划」，拿到的就是**当下这一刻**真实的预计上市日，而不是建项目时的理想值。

---

## 六、生成首单备货草稿

新品要下第一笔货时，在项目里填数量，点 **「生成首单备货草稿」**。

系统会：

1. 校验项目已经设置了**目标 SKU**且该 SKU 已建档（没有就报错并提示先补）；
2. 生成一张**备货申请（BH）草稿**，备注里自动带上项目名和项目编号；
3. 写审计。

生成的是**草稿**，不是已批准的单据。它会走**正常的审批流程** —— 需要人工确认后提交审批。这是有意设计：自动化只出草稿，闸门永远是人。

---

## 七、项目状态

项目本身有三种状态：**进行中 `active` / 已完成 `done` / 已取消 `cancelled`**。
在项目上可以「标记完成」或「取消项目」，同样写审计。

---

## 八、常见问题

**Q：建项目时报「NPD 节点模板为空」？**
A：说明节点模板还没导入。需要先把《各节点核心说明》导入系统（`transit_refs`，kind=`npd_node`），再建项目。

**Q：目标 SKU 还没建档，能先建项目吗？**
A：能。SKU 留空即可，节点照常推进。只是在生成首单备货草稿前必须补上。

**Q：我改了节点模板，在跑的项目会变吗？**
A：不会。模板在建项目时已经快照进项目，在跑的项目不受影响。

**Q：预计完成日怎么算的？**
A：项目里所有节点中**最晚的那个计划完成日**。执行有偏差时点「重排计划」刷新。

**Q：跳过的节点会不会让项目显得提前完成？**
A：跳过 = 零工期直通，它不占时间也不推迟后面的节点，后继节点按上一个有工期的节点顺延。

## 九、目前的边界（如实说明）

- 模板节点的**负责部门**只是文字标注，系统**不会**按部门自动派单或发通知给具体的人。
- **不做**跨项目的产能／资源冲突检测 —— 两个项目同一周撞在一起，系统不会提示。
- 首单备货草稿**只生成一张 BH**，不会自动往下生成采购或委外单据；那些仍走各自的正常流程。
