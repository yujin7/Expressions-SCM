**注意这是两个不同的动作**，此前笼统说成"全部缺权限"会让人做错事：

1. **IP 白名单**：以当次聚水潭 `110` 错误里返回的 IP 为准，加入应用详情 → IP 白名单。
   出库单（每日销量，最要紧的一条）只差这个。
   ⚠ 这是当前开发机的出口 IP；部署到服务器后要换成那台机器的固定公网 IP，否则会重新报 110。
2. **API 权限申请**：应用详情 → API权限申请，勾选店铺查询 / 仓库查询 / 库存查询 /
   普通商品资料查询 / 采购入库查询五条。

### 库存那条即便批下来也不会自动启用

你已说明**聚水潭只有「一仓」的数据准**。而 `/open/inventory/query` 不带 `wms_co_id`
时返回的是**全仓合计**——把准仓与不准仓加在一起且拆不开，看起来却像完整库存总量。
系统已按这条事实设闸（`JST_TRUSTED_WMS_CO_IDS`）：需逐仓拉取，
或业务确认"所有仓都准"（填 `ALL`）才放行。当前填的是具体仓号，不是 ALL。

## 关于"实测证据"字段

`*_LIVE_VERIFIED_AT` / `*_LIVE_VERIFIED_REF` 用于记录“当前配置指纹下，真实业务链路已完成验收”。
当前飞书已有效；简道云、聚水潭和用友仍为 `missing`，不得手工填绿。
系统会校验证据编号必须绑定当前应用+目标对象的指纹，填错或过期会自动阻塞。
在授权真正打通、跑过一轮真实数据之前填这些字段，等于自己骗自己——所以留空。
