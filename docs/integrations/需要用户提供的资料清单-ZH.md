# 需要用户提供的资料清单（精确版）

更新日期：2026-08-03
原则：密码、secret、token 不再发到聊天，不写文档或 Git；只放部署密钥库或本机未跟踪 `.env`。

## 一、当前凭据结论

| 系统 | 已有 | 仍缺 | 结论 |
|---|---|---|---|
| 飞书 | 应用凭据已完成只读鉴权；应用已启用、上线且默认能力为机器人 | 专用最小权限应用（或共享应用权限裁决）、API 可见测试群、`FEISHU_CHAT_ID`、真实投递 | 现有共享应用有 1,107 项权限且实测仍为 0 群；不得直接标为生产安全 |
| 简道云 | OpenAPI 已只读验证 9 应用/297 表单，九条最小字段契约已隔离演练 | 轮换已暴露 token、权威视图裁决、业务控制总量/crosswalk/UAT | 2026-08-03 技术控制量复核稳定；只能作为历史观察源，不得直写正式事实 |
| 聚水潭 | 官方文档链接 | `app_key`、`app_secret`、`access_token`、IP/接口授权、责任人 | 没有机器凭据 |
| 用友 | C4 人工入口及 AppKey/AppSecret 对的一部分 | 企业 OpenAPI 授权、租户/组织、base/token URL、接口与沙箱 | 人工登录或两项密钥都不等于完整 API 上下文 |

## 二、必须由你或企业管理员提供

### A. 飞书（最少只需完成一种路径）

推荐应用机器人路径：

1. 优先创建专用 SCM 通知应用；若必须复用现有共享应用，先由安全/应用责任人裁决其
   1,107 项权限并留下非秘密批准证据，不要由自动化擅自删权；
2. 在飞书创建一个测试群，并把选定应用机器人加入该群；
3. 确认应用已发布，只保留 `im:chat:readonly`（或官方等价群信息权限）、
   `im:message:send_as_bot`（或官方等价消息权限）与只读自检所需的
   `application:application:self_manage`；若不保留自检权限，探针会保守地把应用/权限证据标为
   未知，不会据此宣称可安全生产；
4. 运行 `npx tsx src/jobs/cli.ts probe-feishu-chats`，确认权限聚合不再被阻塞，并把选定群的 `chat_id`
   写入密钥库的 `FEISHU_CHAT_ID`；
5. 告诉我允许发送一条标题带“SCM UAT”的测试消息；
6. 指定该群的业务责任人姓名。

替代路径：提供目标群自定义机器人 `FEISHU_WEBHOOK_URL`，并确认允许一条 UAT 消息。

> 应用鉴权、启用状态、在线机器人版本和两项必需权限已经由官方 API 证明，但只读群目录仍
> 返回 0；这说明投递阻塞是机器人实际可见群，不是再写一套发送代码。现有应用同时严重
> 过度授权，不能把“能鉴权”当成“可安全生产”。若刚修改权限/发布版本/加入群，等待生效后重跑发现命令。
> 不要把凭据粘贴到聊天。验收证据必须绑定实际发送路径：应用机器人填写
> `FEISHU_APP_LIVE_VERIFIED_AT` 与 `FEISHU_APP_LIVE_VERIFIED_REF`；群自定义机器人填写
> `FEISHU_WEBHOOK_LIVE_VERIFIED_AT` 与 `FEISHU_WEBHOOK_LIVE_VERIFIED_REF`。旧的未绑定路径
> `FEISHU_LIVE_VERIFIED_AT` / `FEISHU_LIVE_VERIFIED_REF` 不再接受。这些字段只能在真实投递与
> 失败恢复验收后成对填写；REF 只放非秘密工单/验收编号。应用机器人路径还必须把探针输出的
> `send.expectedEvidenceBinding` 原样放在 REF 末尾（例如 `UAT-工单号-FST1_...`），使证据绑定
> 当前应用与目标群；缺少、错群或旧绑定均不会通过。应用机器人还要在权限确实收敛后填写
> `FEISHU_APP_PERMISSION_REVIEWED_AT` 与 `FEISHU_APP_PERMISSION_REVIEWED_REF`，并把探针输出的
> `permissionReview.expectedEvidenceBinding`（`FSP2_...`）放在 REF 末尾；它绑定应用及规范化权限
> 名称+等级指纹，同一应用权限变化、换应用或过期都会自动阻塞，须以同次只读探针重新复核。

### B. 简道云

1. 轮换已通过聊天传递的 OpenAPI key 与 MCP URL token；旧值立即失效；
2. 新 key 仅存部署密钥库，并限制为只读、最小应用/表单范围及 IP 白名单；
3. 为以下九条契约各指定唯一权威 app view：产品、采购需求、采购订单、采购入库、
   供应商、仓库、调拨、盘点、样品；
4. 各提供一份同一时间点的人工导出控制总量：主表行、子表行、数量、金额、更新时间、
   删除/作废数；
5. 提供简道云 SKU、供应商、仓库编码与 SCM 主档的 crosswalk；
6. 确认 2023–2024 历史行仅供迁移/观察，不能冒充 2026 当前库存或订单；
7. 指定同步责任人用户 ID，并完成改表、空表、限流、重放、失败恢复 UAT。

> UAT 通过后，`JIANDAOYUN_LIVE_VERIFIED_REF` 必须以 `audit-connectors` 输出的当前
> `expectedLiveVerificationBinding`（`JDY1_...`）结尾。任何契约增删都会使旧证据失效并要求重验。

当前只读控制审计已可重复执行：

```bash
npx tsx src/jobs/cli.ts audit-jiandaoyun-contracts
```

2026-08-03（上海时间）复核仍为 128 条主表、131 条子表；最新更新时间 2024-12-11。若简道云仍是当前
低代码 ERP，请提供当前正在录入的应用/表单视图，或调整 API key 授权范围；现有视图不能
证明覆盖 2026 年业务。

### C. 聚水潭

请在聚水潭开放平台/密钥库准备以下值：

1. `JST_APP_KEY`
2. `JST_APP_SECRET`
3. `JST_ACCESS_TOKEN`
4. token 过期时间、续期/刷新方法和轮换责任人；
5. 已授权商家/店铺范围；
6. 已批准接口：销售出库查询、商品库存查询、仓库查询；
7. 生产调用出口 IP 已加入白名单的证明；
8. 聚水潭是否启用生产批次管理；
9. SCM 内同步责任人：姓名或用户 ID（用于 `JST_SYNC_ACTOR_ID`）；
10. 指定一个真实对账日期，并提供该日人工导出的控制总量：订单数、明细数、出库数量。

安全交付方式：把 1–3 写入部署密钥库/本机 `.env`，只告诉我“已配置”，不要粘贴到聊天。

### D. 用友

你已提供人工登录资料和一对 AppKey/AppSecret；前者只能用于人在 C4/YonSuite 页面操作，
后者仍缺企业授权上下文。API 接入还需要：

1. 企业书面/明确批准开放平台开发者或企业应用注册；
2. 实际产品与版本：C4 / YonSuite / YonBIP；
3. `YY_APP_KEY`
4. `YY_APP_SECRET`
5. `YY_TENANT_ID`
6. `YY_ORG_ID`
7. `YY_PRODUCT_PROFILE`：由实施方确认 `c4` / `yonsuite` / `yonbip`；
8. `YY_APPROVED_API_CONTRACTS`：企业已授权的精确 API 名称/版本，逗号分隔；
9. `YY_ALLOWED_HOSTS`：企业确认的 base/token 精确主机名，不接受通配符或 IP；
10. `YY_BASE_URL`
11. `YY_TOKEN_URL`
12. 沙箱企业/账套和生产企业/账套；
13. 获批 API 的官方路径、字段文档与授权证明；
14. 先接入哪些范围：成本读取、供应商/货品主档、凭证、委外结算（请排序）；
15. 组织、账簿、币种、税率、会计期间的口径；
16. SKU/供应商与用友编码的对照导出；
17. IP 白名单、限流、回调验签、错误码与 token 生命周期；
18. 用友实施顾问/企业管理员的联系人。

可先运行 `npx tsx src/jobs/cli.ts audit-yonyou-readiness` 做无网络、无 secret 输出的前置审计。
在 1、2、7–14 未确认且沙箱只读对账未通过前，系统不会开启财务写入。

## 三、SKU 与数据治理需要你确认

### 必须

1. 品牌短码最终表：每个品牌的唯一 2–4 位大写字母/数字码；当前候选为
   `NING / EXP / DEV / B2F / LYUV / ABS / DWS / WC`；
2. “共享/中性物料”是否统一用 `GEN`；
3. 两个真实试点产品：品牌、SPU/SKU、负责人；
4. 重复条码归属裁决表：每个重复条码最终属于哪个 SKU，或明确作废；
5. 聚水潭、用友、供应商/客户历史编码与内部 SKU 的对照导出；
6. 简道云各权威表单中的 SKU、供应商和仓库编码对照；
7. 7 月末样品、赠品、试用装、内用 SKU 清单。

### 后续点亮高级能力时必须

8. 渠道售价与生效日期；
9. 促销/活动日历、活动类型、折扣和活动 SKU；
10. 客户销售承诺/订单优先级；
11. 渠道缺货分配优先级及例外；
12. 最终单位成本、币种、税口径与资金成本；
13. NPD 每日/节点真实进度与上市日期；
14. 海外仓、保税仓、部门仓完整清单及库存粒度；
15. 真实物流周期、MOQ、订货倍数、保质期和临期阈值。

## 四、真实上线验收需要你安排

1. 指定业务、供应链、财务三类 UAT 用户；
2. 安排两款产品从申请、委外、采购、发料、收货、入库、结算到对账的完整试跑；
3. 简道云九条观察契约逐表控制总量、重复视图裁决、schema 漂移与恢复演练；
4. 聚水潭连续 7 天同步/恢复演练和 14 天逐日对账窗口；
5. 飞书测试群投递、去重、失败恢复验收；
6. 用友先只读对账，通过后再批准提交；
7. 最终上线签字人：业务、供应链、财务、系统管理员。

## 五、系统可自行完成，不需要你提供

- S1 自动取号、校验码、并发防重；
- GTIN Mod-10 校验和包装层级管理；
- 外部编码/历史编码登记、搜索、导入解析；
- 重复归属拦截、审计留痕、停用不删除历史；
- 代码测试、迁移、构建、GitHub PR 与受保护分支合并；
- 凭据 readiness 检查（只报告缺失字段，不输出 secret）。
