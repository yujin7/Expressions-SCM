# 简道云外部需求 UAT 操作手册

适用范围：天猫 SKU 日销量、成功退款、平台 SKU 对照三个只读观察契约。  
目标：证明同一截止日下，SCM 的观察信号与平台/简道云导出一致，并把身份缺口交给明确负责人。

> 本手册不授权数据升格。完成核对前，数据固定为 `observation_only`，不得写正式销量、库存、
> 财务或自动补货。本文不记录 API Key、账号、密码或 token。

## 1. 角色与输入

| 角色 | 必须提供/完成 |
|---|---|
| 电商数据 owner | 从平台或简道云导出与 SCM **同一业务截止日**的日销量、退款和 SKU 对照 |
| 商品运营 | 处理高需求未映射 SKU；有条码的认领，无条码的回源补齐 |
| PMC | 复核净需求口径和残余未映射量是否会改变计划判断 |
| 系统管理员 | 运行同步、保存非秘密证据编号、确认失败重放与权限边界 |

在 SCM 打开：`经营分析 → 决策工作室 → 外部需求信号`。

## 2. 下载两份系统证据

1. 在“简道云 · 天猫支付、退款与净需求趋势”右上角点击下载，取得
   `简道云-天猫需求-UAT日核对-*.csv`。
2. 在“优先处理：高销量未映射平台 SKU”点击“导出修复队列”，取得
   `简道云-天猫SKU身份修复-*.csv`。
3. 确认两份文件的 `来源截止`、`对照截止`、`权限口径` 和 `放行状态` 非空；
   `权限口径` 必须为 `observation_only`。
4. 文件名和文件内都有截止日与生成时间；不要把旧文件覆盖成“最新版”。

若按钮不可用，先看页面门禁：缺任一最新成功批次时禁止用 0 替代，也禁止继续验收。

## 3. 日控制总量核对

平台导出必须使用与 `来源截止` 相同的结束日期，并明确时区、店铺范围、是否含取消未付款、
退款成功定义和数量单位。逐日核对以下四列：

| 字段 | SCM 公式 | 验收要求 |
|---|---|---|
| 支付件数 | 简道云 `paidNumber` 合计 | 与同范围源导出一致 |
| 成功退款件数 | `successRefundSuborderNumber` 合计 | 与同范围源导出一致 |
| 净需求信号 | 支付件数 − 成功退款件数 | 逐日重算一致 |
| 已映射净需求 | 只含可唯一归属 SCM SKU 的净需求 | 不得大于总净需求；差额可追到身份队列 |

差异记录模板：

| 日期 | 字段 | SCM 数量 | 源导出数量 | 差异 | 原因分类 | Owner | 处理期限 | 证据编号 |
|---|---|---:|---:|---:|---|---|---|---|
| YYYY-MM-DD | 支付/退款 |  |  |  | 时区/范围/迟到更新/字段口径/未知 |  |  |  |

不得用不透明容差把差异“调平”。所有非零差异必须能归入明确原因并附原始导出 hash 或内部证据编号。

## 4. 身份修复

按导出文件的 `下一步动作` 执行：

- `去认领`：点击系统异常页，按完整 `JIANDAOYUN + sku_barcode + rawValue` 选择唯一 SCM SKU；
- `回源补对照/条码`：在平台/简道云主档补正确条码或平台 SKU 对照；
- `已认领·待同步`：不要改旧 staging，重新同步“天猫 SKU 对照”；
- `已忽略·回源核对` / `待同步核对`：由商品 owner 查原单、包装层级和条码后裁决。

先处理 TOP 30，再按支付件数覆盖推进长尾。系统不按相似名称、短码或跨来源全局别名自动认领。

## 5. 必须停止的情况

出现任一项即停止放行：

- 来源/对照截止日不一致或源导出范围无法证明；
- 非法销售/退款数值或冲突对照数不为 0；
- 同一店铺 + 平台 SKU 指向多个条码或多个 SCM SKU；
- 已映射数量大于总体数量；
- 旧批次记录被改写，或重新同步后无法重放得到相同结果；
- 差异只能靠手工改数、删行或用 0 填未知来消除。

## 6. 完成证据

一次 UAT 只有同时具备以下内容才可签认：

- 两份 SCM CSV 和三份同截止日源导出；
- 每份文件的 SHA-256 或受控文档版本；
- 日控制总量差异表，所有非零差异有 owner、原因和处理结论；
- TOP 30 身份逐项处置结果，以及新对照批次的覆盖变化；
- 一次失败后重跑/幂等证据；
- 电商数据 owner、商品运营、PMC、系统管理员签认；
- 非秘密证据编号，例如 `UAT-YYYYMMDD-JDY-DEMAND-001`。

固定通过阈值不由工程侧擅自设定。业务须在签认中明确允许的身份/支付量覆盖目标和残余风险；
在目标获批前，系统继续保持观察级，不自动升格。
